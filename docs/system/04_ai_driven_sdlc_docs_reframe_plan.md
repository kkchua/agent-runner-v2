# 04 Reframe SDLC Docs Around `00_master_docs_bootstrap_v2`

## Summary

Revise `docs/system/02_ai_driven_sdlc_structure_proposal.md` and
`docs/system/03_ai_driven_sdlc_migration_plan.md` so they no longer imply SDLC
structure can be introduced independently of Layer 2 bootstrap. Both documents
should explicitly state that `00_master_docs_bootstrap_v2` is the prerequisite
repo master-doc bootstrap, that it owns the initial repo-level SDLC operating
contract under `docs/repo/sdlc/00_governance/`, and that downstream SDLC
workflow-family work starts only after that Layer 2 baseline exists.

This reframe should also align with the current repo reality: Layer 1
governance is now present, `00_master_docs_bootstrap_v2` is planned and
archived but not live under `workflows/`, and the SDLC documents are currently
describing a target structure that lacks its required Layer 2 owner.

## Key Changes

- Update both SDLC docs to make the dependency chain explicit:
  - Layer 1: `00_layer1_governance_bootstrap_v1`
  - Layer 2: `00_master_docs_bootstrap_v2`
  - Layer 3+: SDLC workflow-family split (`10_requirement_intake_v1`,
    `20_planning_v1`, etc.)

- Change the ownership model in both docs:
  - remove the implication that a separate future "SDLC governance bootstrap
    workflow" creates the first `docs/repo/sdlc/00_governance/*` contract
  - state that `00_master_docs_bootstrap_v2` generates the initial Layer 2 repo
    operating baseline, including the SDLC governance package
  - position later SDLC workflows as consumers of that baseline, not creators
    of it

- Revise the proposed `docs/repo/sdlc/00_governance/` section so its files are
  framed as Layer 2 repo master docs:
  - `README.md`
  - `SDLC_WORKFLOW_SOP.md`
  - `SDLC_STATUS_RULES.md`
  - `SDLC_FOLDER_MAP.md`
  These should be described as repo-level operating contracts produced during
  master-doc bootstrap, then extended or referenced by downstream workflow
  families.

- Rewrite the migration sequencing in the migration-plan doc:
  - add a new first migration phase for "restore/complete
    `00_master_docs_bootstrap_v2` as live workflow package"
  - move SDLC path canonicalization behind that phase
  - move specialized workflow-family rollout behind both Layer 2 bootstrap and
    path-foundation readiness
  - replace "create the SDLC governance workflow bundle" with "extend
    `00_master_docs_bootstrap_v2` to emit the SDLC governance baseline"

- Add a current-state correction section in both docs:
  - `workflows/00_master_docs_bootstrap_v2` is not currently present in the
    live repo root
  - the workflow exists only in `archive/` plus prior planning/tests
  - this makes `00_master_docs_bootstrap_v2` a prerequisite
    recovery/completion item, not a completed dependency

- Align terminology with Layer 2 scope:
  - `00_master_docs_bootstrap_v2` owns repo-level structure, operating
    understanding, and the initial SDLC contract
  - it does not own Layer 1 ecosystem rules
  - it does not own run-local or task-local artifacts generated by later
    workflow families

## Important Interfaces / Contracts

- Documented dependency order becomes part of the intended repo contract:
  - no SDLC folder canonization plan should assume
    `docs/repo/sdlc/00_governance/*` exists before
    `00_master_docs_bootstrap_v2`
  - no downstream workflow-family plan should claim ownership of the initial
    repo-level SDLC governance package

- The documented output contract for `00_master_docs_bootstrap_v2` should be
  expanded to include the initial SDLC governance baseline under
  `docs/repo/sdlc/00_governance/`, alongside the broader repo master-doc set.

- The migration-plan doc should treat `docs/repo/sdlc/*` as a target runtime
  structure whose repo-level governance root is established by Layer 2
  bootstrap first, then used by path constants, validators, and specialized
  workflow bundles.

## Test Plan

- Review both revised docs for consistency on the prerequisite order:
  - every dependency chain names Layer 1 before Layer 2 before SDLC workflow
    families
  - no section reintroduces a standalone initial SDLC-governance bootstrap
    owner

- Verify ownership consistency:
  - `docs/repo/sdlc/00_governance/*` is always attributed to
    `00_master_docs_bootstrap_v2`
  - specialized SDLC workflows only own their phase/domain artifacts

- Verify current-state accuracy:
  - both docs acknowledge that the live `workflows/00_master_docs_bootstrap_v2`
    package is currently absent and must be restored/completed before use

- Verify migration sequencing:
  - no "immediate next step" or phase list tells implementers to create SDLC
    governance separately from master-doc bootstrap
  - runtime-path migration and validator changes occur after the Layer 2
    bootstrap prerequisite is established

## Assumptions

- `00_master_docs_bootstrap_v2` should be treated as the Layer 2 repo
  master-doc owner for this repository.
- The archived workflow and existing migration plan are the authoritative basis
  for what that workflow is supposed to become.
- The two SDLC docs remain planning/design artifacts under `docs/system/`; this
  pass reframes their dependency and ownership model rather than converting them
  into generated governance docs.
