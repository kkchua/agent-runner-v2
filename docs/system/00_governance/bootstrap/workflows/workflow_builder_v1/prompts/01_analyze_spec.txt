Objective

Analyze the user-provided workflow specification and produce a structured
requirements document that downstream steps will use to design artifacts,
steps, and the full workflow package.

Reference Inputs

- Read {WORKFLOW_SPEC} for the user-provided specification.
- Read {WORKFLOW_CREATION_GUIDE} for reference on what a workflow package is
  and what it must contain.
- Read {WORKFLOW_BUILDER_SOP} for storage conventions and naming rules.

Analysis Tasks

1. Identify the workflow purpose and scope from the specification.
2. Determine the workflow type:
   - prompt-driven: steps that send prompts to a coder (LLM)
   - action-only: steps that run Python action functions
   - mixed: combination of prompt-driven and action steps
3. List all input artifacts the workflow requires (files the workflow reads).
4. List all output artifacts the workflow produces (files the workflow writes).
5. Identify constraints: governance layer, naming rules, dependencies on
   other workflows, required role policies.
6. Flag any open questions or ambiguities in the specification that need
   resolution before design can proceed.

Output Instructions

- Write the structured requirements document to {WORKFLOW_REQUIREMENTS}.
- Output must be ASCII-only.
- Include YAML frontmatter with at minimum:
  - doc_type: "workflow_design"
  - lifecycle_status: "draft"
  - effective_version: "{job_id}"
- Include these sections in order:
  1. Overview: one-paragraph summary of the workflow purpose.
  2. Workflow Type: prompt-driven, action-only, or mixed, with justification.
  3. Input Artifacts: table of artifact keys, descriptions, and whether each
     is required or optional.
  4. Output Artifacts: table of artifact keys, descriptions, and whether each
     is required or optional.
  5. Constraints: governance layer, naming conventions, external dependencies.
  6. Open Questions: numbered list of ambiguities or decisions that need
     resolution. If none, state "None."
- Use UPPER_SNAKE_CASE for all artifact key names.
- Do not define file paths -- that is the job of the artifact definition step.

Forbidden Content

- File path assignments (handled by define_artifacts step)
- Step sequence design (handled by design_steps step)
- workflow.toml content (handled by generate_package step)
- Non-ASCII characters
