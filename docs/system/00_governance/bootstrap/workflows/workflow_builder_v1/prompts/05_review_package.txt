Objective

Review the generated workflow package for quality, consistency, and
compliance with the workflow creation guide. Produce a detailed review
document with an APPROVED or REJECTED verdict.

Reference Inputs

- Read {WORKFLOW_MANIFEST} for the generated workflow.toml.
- Read {WORKFLOW_EXTENSIONS} for the generated context_extensions.py.
- Read {WORKFLOW_PROMPTS_INDEX} for the list of generated prompt files.
- Read {VALIDATION_REPORT} for automated validation results.
- Read {WORKFLOW_CREATION_GUIDE} Part E (Common Pitfalls) for the review
  checklist.

Review Checklist

1. workflow.toml checks:
   - stepCompletion terminal step is present as the last [[step]]
   - init_step matches the first step name
   - Every onsuccess target references a valid step name or stepCompletion
   - promotes key is at [[step]] top level, not inside [step.artifacts]
   - onsuccess is at step level, not inside [step.artifacts]
   - Every prompt step has [step.coder] with a valid role_policy
   - Every prompt step has [step.artifacts] with produces and result_meta_key
   - Review steps have requires_human_approval_after and [step.on_reject_refine]
   - Refine steps have loop_returns_to pointing to the review step
   - Step names are lowercase_with_underscores and unique

2. context_extensions.py checks:
   - WorkflowExtensions class is present and inherits correctly
   - workflow_name matches the workflow directory name
   - register_artifact_keys() returns relative paths with {job_id}, {seq},
     {slug} placeholders
   - build_context_extensions() returns absolute paths
   - install_to_global() method is present
   - sync_to_backend() method is present
   - All artifact keys from workflow.toml produces lists appear in
     register_artifact_keys()
   - Module, class, and methods have docstrings

3. Prompt file checks:
   - Every prompt file listed in the index exists
   - Placeholders use bare {KEY} format, never backtick-wrapped
   - All content is ASCII-only
   - Each prompt has Objective, Reference Inputs, and Output Instructions
   - Artifact key references in prompts match keys in the artifact contract

4. Cross-file consistency:
   - Artifact keys are consistent between workflow.toml and
     context_extensions.py
   - Step names in workflow.toml match prompt file naming convention
   - Routing targets in workflow.toml reference existing step names

Output Instructions

- Write the review document to {REVIEW_FILE_SUGGESTED}.
- Output must be ASCII-only.
- Include YAML frontmatter with at minimum:
  - doc_type: "workflow_review"
  - lifecycle_status: "draft"
  - effective_version: "{job_id}"
- Include these sections:
  1. Summary: one-paragraph overall assessment.
  2. workflow.toml Findings: pass/fail for each check with evidence.
  3. context_extensions.py Findings: pass/fail for each check with evidence.
  4. Prompt File Findings: pass/fail for each check with evidence.
  5. Cross-File Consistency: pass/fail for each check with evidence.
  6. Issues: numbered list of specific issues to fix (if any).
  7. Verdict: APPROVED or REJECTED on its own line at the end.
- If REJECTED, each issue must include the file, location, and specific fix
  required.

Decision Rules

- APPROVED: All checks pass or have only minor cosmetic notes that do not
  affect functionality.
- REJECTED: Any missing required element, key mismatch, routing error,
  backtick-wrapped placeholders, or non-ASCII content.

CRITICAL: The meta.json status field MUST match your review verdict exactly.
- If your review document says APPROVED, set meta.json status to "APPROVED".
- If your review document says REJECTED, set meta.json status to "REJECTED".

Forbidden Content

- Modifying workflow files directly (that is the refine step)
- Vague findings without specific file and location references
- Non-ASCII characters
