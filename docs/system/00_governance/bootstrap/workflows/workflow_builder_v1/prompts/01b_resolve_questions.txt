Objective

Perform a second pass on the structured requirements document. Re-read the
source specification to resolve open questions, fill gaps, and produce a
complete requirements document that downstream steps can use without
ambiguity.

Reference Inputs

- Read {WORKFLOW_SPEC_FILE} for the original specification (read it fully).
- Read {WORKFLOW_REQUIREMENTS} for the step 1 output that needs updating.
- Read {WORKFLOW_CREATION_GUIDE} for workflow package conventions.

Resolution Tasks

1. Open every section of the source specification. For each Open Question
   in the requirements document:

   a. If the answer exists in the specification:
      - Resolve the question.
      - Update the relevant section of the requirements document with the
        resolved information.
      - Move the question to the "Resolved Questions" section with a brief
        note of where the answer was incorporated.

   b. If the answer is a design decision not covered by the specification:
      - Write a detailed proposal with:
        * Recommended approach (with justification)
        * Alternative approaches considered
        * Trade-offs and risks
      - Move the question to the "Design Decisions Required" section with
        the full proposal.

2. Fill gaps from the specification that step 1 missed:

   a. Context Variables: If the spec declares context variables (directory
      paths, config references), add a "Context Variables" section listing
      each variable and its purpose. Do NOT include resolved file paths --
      just the variable names and descriptions.

   b. JSON Schemas: If the spec defines output schemas (e.g., description
      JSON structure, variant JSON structure), add a "Data Schemas" section
      summarizing the key fields and their purposes. Do NOT reproduce the
      full schema -- summarize the structure and field count.

   c. Implementation Hints: If the spec references reusable scripts, legacy
      prompts, or API patterns, add an "Implementation Notes" section
      listing these references.

3. Verify consistency:
   - Every artifact key in Input/Output tables must be traceable to the spec.
   - Remove any artifact keys that were inferred but not supported by the spec.
   - Ensure the Workflow Type classification matches the actual step types
     described in the spec.

Output Instructions

- Overwrite {WORKFLOW_REQUIREMENTS} with the updated document.
- Output must be ASCII-only.
- Preserve the YAML frontmatter (update effective_version if needed).
- Preserve all sections that are already correct.
- Replace the "Open Questions" section with two new sections:
  1. "Resolved Questions" -- questions answered from the spec.
  2. "Design Decisions Required" -- proposals for human review.
- If all questions are resolved and no design decisions are needed, state
  "All questions resolved. No design decisions required."
- Use UPPER_SNAKE_CASE for all artifact key names.

Forbidden Content

- File path assignments (handled by define_artifacts step)
- Step sequence design (handled by design_steps step)
- workflow.toml content (handled by generate_package step)
- Non-ASCII characters
- Inventing scope not traceable to the specification
