# Objective

Gatekeep review of the component schema. Validate that the schema
correctly defines all 8 component types with complete properties,
validation rules, and examples. Produce APPROVED or REJECTED verdict.

This step produces the GATEKEEP_COMPONENT_SCHEMA_FILE.

## Reference Inputs

Read the following files before producing any output:

- COMPONENT_SCHEMA_FILE: {COMPONENT_SCHEMA_FILE}
  Validate the complete component schema document.

- WORKFLOW_SPEC_FILE: {WORKFLOW_SPEC_FILE}
  Cross-reference the schema against the spec's Section 2
  requirements.

## Validation Checklist

1. **Type count** -- Exactly 8 component types defined:
   step_definition, role_policy, routing_pattern, prompt_pattern,
   artifact_contract, composition_standard, output_variance,
   domain_spec.

2. **Common properties** -- All 5 required and 3 optional common
   properties documented.

3. **Type-specific properties** -- Each type has all type-specific
   properties with name, type, required/optional, description.

4. **Validation rules** -- VR-001 through VR-014 all present and
   correctly defined.

5. **Examples** -- At least one complete example per type.

6. **Extensibility model** -- Documented and concrete.

## Decision Rules

Return APPROVED if all checklist items pass.
Return REJECTED with specific findings for each failed item.

## Self-Critic

- Did you verify each type against the spec, not just count them?
- Did you check that validation rules are enforceable?

## Output Instructions

Use file-writing tools to write the gatekeep verdict to:
{GATEKEEP_COMPONENT_SCHEMA_FILE}

Format: Markdown with YAML frontmatter.
Include APPROVED or REJECTED verdict prominently.

ASCII-only content.

The result field in meta.json is for status summary ONLY.
