Objective

Execute the task per the approved implementation plan and document the execution results.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2 platform contract.
- Execute only per the approved implementation plan, not inventing new scope.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only reference inputs.

Reference Inputs

- Read `IMPL_FILE` (approved implementation plan).
- Read codebase context from `docs/repo/codebase/current/` to understand repository structure.
- Read Layer 1 governance at `GOVERNANCE_RUNTIME_ROOT` for metadata requirements.
- Read Layer 2 platform constitution at `PLATFORM_RUNTIME_ROOT` for platform contract.

Execution Document Requirements

The EXEC document must include:

1. YAML Frontmatter (REQUIRED):
   - `template_id: "SYS-03-EX"`
   - `version: "1.0.0"`
   - `doc_type: "workflow_output"`
   - `authority: "workflow-generated"`
   - `scan_policy: "include"`
   - `scan_reason: "execution record for task completion"`
   - `layer: "layer3"`
   - `platform: "agent-runner-v2"`
   - `lifecycle_status: "draft"`
   - `effective_version: "{job_id}"`
   - `managed_by: "workflow-generated"`

2. Required Sections (in this exact order):
   - `Execution Overview` - High-level summary of what was executed
   - `Implementation Traceability` - Link back to approved IMPL and steps
   - `Execution Steps` - Detailed record of each step performed
   - `Code Changes Made` - Specific files changed and what was changed
   - `Test Files Created` - Test files written to the codebase from the IMPL test implementation
   - `Test Execution Results` - Actual test output and pass/fail results
   - `Issues Encountered` - Any issues found during execution
   - `Rollback Status` - Whether rollback was needed or available
   - `Verification` - How execution was verified against acceptance criteria
   - `Open Questions` - Unresolved items that need clarification

3. Content Guidelines:
   - Execute only per the approved implementation plan
   - Implement all code changes specified in the IMPL document
   - Create test files in the codebase from the test implementation section
     of the IMPL document (write actual test files to tests/ directory)
   - Run the test suite after implementation: .venv\Scripts\python -m pytest tests/unit/ -x -q
   - Record actual test output (not fabricated results) with pass/fail status
   - Document all changes made with specific file paths
   - Note any deviations from the plan
   - Capture lessons learned for future executions
   - Verify API and SDK usage against the actual installed library version
     by reading the source code or documentation in the virtual environment.
     Do not rely on training data for library APIs -- they may have changed.

Output Instructions

- Write the execution document to `EXEC_FILE` path.
- Use ASCII-only characters (no em-dashes, curly quotes, or Unicode).
- Use plain text section headings (no backticks or formatting in headings).
- Keep terminology consistent with Layer 1 and Layer 2 governance docs.
- Do not create validation artifacts or review documents.

Forbidden Content

- Layer 1 governance redefinition or contradiction
- Layer 2 platform contract redefinition
- Scope not covered by the approved implementation plan
- Validation reports or review documents
- Content not supported by the approved implementation
