Objective

Fix all issues identified in the review document AND the deterministic
validation report. Update the generated workflow package files in-place to
resolve each finding. Focus on root causes, not just symptoms.

Reference Inputs

- Read {REVIEW_FILE_SUGGESTED} for the list of issues to fix.
- Read {VALIDATION_REPORT_FILE} for deterministic validation findings (if it
  exists -- this contains static analysis results like TYPE_CHECKING import
  errors, artifact binding inconsistencies, syntax errors).
- Read {WORKFLOW_MANIFEST_FILE} for the current workflow.toml content.
- Read {WORKFLOW_EXTENSIONS_FILE} for the current context_extensions.py content.
- Read {WORKFLOW_ACTIONS_FILE} for the current actions.py content (if it exists).
- Read {WORKFLOW_PROMPTS_INDEX_FILE} for the list of generated prompt files.
- Read {WORKFLOW_README_FILE} for the current README.md content.
- Read {WORKFLOW_ENV_SAMPLE_FILE} for the current .env.sample content (if it
  exists).
- Read {WORKFLOW_CONFIG_SAMPLE_FILE} for the current config.json.sample content
  (if it exists).
- Read {OPERATIONAL_WORKFLOW_FILE} for the operational workflow design (if
  needed to verify design fidelity).

Root Cause Fix Rules

For each issue in the review:

1. Identify the ROOT CAUSE, not just the symptom.
   - Example: "NameError at runtime" is a symptom. Root cause: "import is
     inside TYPE_CHECKING block."
   - Example: "artifact binding mismatch" is a symptom. Root cause: "step
     declares artifact in both required_inputs and produces."

2. Fix the root cause so the symptom cannot recur.
   - Do NOT just patch the specific line -- check if the same pattern appears
     elsewhere in the file.
   - If the review flags one TYPE_CHECKING import, check ALL imports in the
     file for the same issue.
   - If the review flags one artifact binding error, check ALL step bindings.

3. Verify the fix does not introduce new issues.
   - After changing imports, verify all function calls still resolve.
   - After changing artifact bindings, verify the full chain is consistent.
   - After changing early-exit logic, verify downstream steps handle empty
     artifacts correctly.

Refinement Rules

1. Address every issue listed in the review document explicitly.
2. Address every ERROR-level finding in {VALIDATION_REPORT_FILE}.
3. Do not change content that was not flagged by the review or validation.
4. Maintain consistency across all files -- if you change an artifact key in
   one file, update it in all files that reference it.
5. Preserve the overall workflow structure. Do not add new steps, remove
   existing steps, or restructure the routing unless the review specifically
   requires it.
6. Keep all content ASCII-only.
7. If the review flagged backtick-wrapped placeholders, replace them with
   bare {KEY} format.
8. If the review flagged missing artifact keys, add them to both
   workflow.toml and context_extensions.py.
9. If the review flagged routing errors, correct the step references.
10. If the review flagged README.md issues (missing sections, wrong step
    table, incorrect artifact keys), update {WORKFLOW_README_FILE} in-place.
11. If the review flagged .env.sample issues (missing variables, bad comments,
    or file should not exist), update or remove {WORKFLOW_ENV_SAMPLE_FILE}
    accordingly.
12. If the review flagged config.json.sample issues (invalid JSON, missing
    settings, or file should not exist), update or remove
    {WORKFLOW_CONFIG_SAMPLE_FILE} accordingly.
13. If the review or validation flagged missing actions.py, generate
    {WORKFLOW_ACTIONS_FILE} with proper @action decorated functions per the
    action specifications in {OPERATIONAL_WORKFLOW_FILE}. Include error
    handling, input validation, and ActionResult returns.
14. If the review or validation flagged incomplete action implementations
    (stubs instead of actual logic), update {WORKFLOW_ACTIONS_FILE} with
    complete implementations.
15. If the validation report flagged TYPE_CHECKING imports used at runtime,
    move ALL runtime-needed imports to the top level of actions.py.
16. If the validation report flagged self-referential artifact bindings,
    remove the artifact from required_inputs (keep it in produces only).
17. If the review flagged prompt quality issues (ambiguous output instructions,
    missing file-writing instructions), update the affected prompt files.
18. If actions.py is created or modified, update {WORKFLOW_PROMPTS_INDEX_FILE}
    to reflect the new file.

Code Quality Verification (After Fixes)

After applying all fixes, verify:

1. No runtime imports inside TYPE_CHECKING blocks in actions.py.
2. No self-referential artifact bindings in workflow.toml (no key in both
   required_inputs and produces of the same step).
3. Early-exit paths return empty artifacts dict, not placeholder files.
4. All @action functions have the @action("name") decorator.
5. All @action functions return ActionResult (not None, not dict).
6. All artifact keys in workflow.toml are registered in context_extensions.py.
7. All prompt files referenced in workflow.toml exist on disk.

Post-Fix Consistency Check

After making changes, verify cross-file consistency:

1. If you changed an artifact key name in workflow.toml, did you also change
   it in context_extensions.py and any prompt files that reference it?
2. If you added a new step, does it appear in workflow.toml routing, have a
   prompt file (if prompt-driven), and have its artifact keys registered?
3. If you changed an action implementation, does the action name still match
   the workflow.toml reference?
4. Does the README.md still accurately describe the package contents?

Output Instructions

- Update {WORKFLOW_MANIFEST_FILE} in-place with fixes.
- Update {WORKFLOW_EXTENSIONS_FILE} in-place with fixes.
- Update {WORKFLOW_ACTIONS_FILE} in-place if flagged (or create if missing).
- Update any prompt files that were flagged, using the paths from
  {WORKFLOW_PROMPTS_INDEX_FILE}.
- Update {WORKFLOW_PROMPTS_INDEX_FILE} if prompt file listings changed.
- Update {WORKFLOW_README_FILE} in-place with fixes.
- Update {WORKFLOW_ENV_SAMPLE_FILE} in-place if flagged (or remove if the review
  says it should not exist).
- Update {WORKFLOW_CONFIG_SAMPLE_FILE} in-place if flagged (or remove if the
  review says it should not exist).
- Document each fix applied in a summary section at the top of each modified
  file as a comment (for code files) or at the end of the document (for
  markdown files).
- Use ASCII-only characters in all output.

Forbidden Content

- Structural changes not justified by review or validation findings
- Adding new workflow steps
- Removing existing workflow steps
- Changing the workflow name or job_prefix
- Non-ASCII characters
- Runtime imports inside TYPE_CHECKING blocks
- Self-referential artifact bindings
- Placeholder/stub files on early-exit paths
