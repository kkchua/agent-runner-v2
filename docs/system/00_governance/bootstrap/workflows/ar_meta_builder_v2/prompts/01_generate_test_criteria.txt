# Objective

Generate comprehensive acceptance criteria for all 8 design phases of the
AR Meta Builder v2 pipeline. These criteria define what makes each phase's
output correct, complete, and verifiable. This step produces the accumulated
TEST_CRITERIA_FILE used by all subsequent gatekeep steps.

# Reference Inputs

- WORKFLOW_SPEC_FILE: {WORKFLOW_SPEC_FILE}
  Read the entire specification. Pay attention to all sections describing
  component types, binding rules, output format, validation rules, and
  operational requirements.

# Generation Tasks

Produce a test criteria document with these sections:

1. **Introduction** -- Scope and purpose. State these criteria apply to
   the target workflow described in the spec (NOT the builder).

2. **Criteria for Phase 1 (Analyze Spec)** -- Identity correctness,
   output type extraction, meta-test-criteria coverage (4 invariants).

3. **Criteria for Phase 2 (Component Schema)** -- All component types
   defined, 7 common properties, type-specific properties, validation
   rules VR-001 through VR-008.

4. **Criteria for Phase 3 (Composition Format)** -- Binding rules (one
   per type), override mechanism, 7 placeholders, ordering rules.

5. **Criteria for Phase 4 (Output Format)** -- 3-part output structure,
   resolution rules RR-001 through RR-005, quality requirements QR-001
   through QR-012.

6. **Criteria for Phase 5 (Artifact Contract)** -- Key uniqueness,
   filename patterns, no global registry conflicts.

7. **Criteria for Phase 6 (Step Sequence)** -- Routing valid, no
   dangling references, output delivery matches spec type.

8. **Criteria for Phase 7 (Runtime Standard)** -- All phases
   consolidated, identity correct, cross-phase consistency.

9. **Criteria for Phase 8 (Operational Workflow)** -- Steps reference
   standard, prompt files exist, action implementations present.

10. **Negative Criteria** -- Things that MUST NOT appear (builder
    identity leakage, non-ASCII, scope invention, hardcoded types).

11. **Self-Validation** -- Verify coverage of all spec sections and
    all criteria are verifiable by a gatekeeper.

# Self-Critic

- Did you cover all 8 phases?
- Is every criterion specific enough for objective verification?
- Are there vague criteria like "must be correct"?
- Did you include the 4 meta-test-criteria invariants?
- Did you include negative criteria for builder identity leakage?

# Forbidden Content

- Do NOT use "ar_meta_builder_v2" as the target workflow name
- Do NOT use "AMB_STANDARD" as the target standard name
- Do NOT include vague criteria like "must work properly"
- Do NOT include non-ASCII characters
- Do NOT invent requirements beyond what the spec defines

ASCII-only content.
