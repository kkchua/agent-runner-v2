# Objective

Perform a comprehensive quality review of the complete workflow
package. This is the final quality gate before promotion. Check
spec fulfillment, component quality, composition quality, output
quality, data flow, and scope verification.

This step produces the REVIEW_FILE_SUGGESTED.

## Reference Inputs

Read the following files before producing any output:

- WORKFLOW_MANIFEST_FILE: {WORKFLOW_MANIFEST_FILE}
  Review workflow.toml structure and content.

- WORKFLOW_EXTENSIONS_FILE: {WORKFLOW_EXTENSIONS_FILE}
  Review context_extensions.py completeness and correctness.

- WORKFLOW_ACTIONS_FILE: {WORKFLOW_ACTIONS_FILE}
  Review actions.py implementations.

- WORKFLOW_README_FILE: {WORKFLOW_README_FILE}
  Review README.md for completeness and accuracy.

- VALIDATION_REPORT_FILE: {VALIDATION_REPORT_FILE}
  Review deterministic validation findings.

- GATEKEEP_PACKAGE_FILE: {GATEKEEP_PACKAGE_FILE}
  Review gatekeep verdict and findings.

## Review Checklist

### Spec Fulfillment
1. All 9 phases from the spec are represented in the workflow.
2. All 21 steps are present with correct types and routing.
3. All 8 review/refine loops are configured correctly.

### Component Quality
4. Component types in the workflow match the spec.
5. Role policies are correctly assigned (architect for generate,
   reviewer for review, gatekeeper for gatekeep).

### Composition Quality
6. Artifact bindings match the design VERBATIM.
7. No scope shrink (missing steps or artifacts).
8. No scope creep (extra steps or artifacts).

### Output Quality
9. workflow.toml is valid TOML with correct structure.
10. context_extensions.py is valid Python.
11. actions.py is valid Python with @action decorators.
12. README.md documents all steps and artifacts.

### Data Flow
13. Artifact flow chains are valid (no temporal violations).
14. All required_inputs are produced before consumption.

### Cross-File Consistency
15. Step names in workflow.toml match prompt file names.
16. Artifact keys are consistent across all files.

### Scope Check
17. No features beyond what the spec requires.
18. No omitted spec requirements.

## Decision Rules

Return APPROVED if all checklist items pass.
Return REJECTED with specific, actionable findings for each issue.
For each REJECTED item, provide: the file, the section, what is
wrong, and what the fix should be.

## Self-Critic

- Did you read every file thoroughly, not just skim?
- Did you check cross-file consistency, not just individual files?
- Did you verify scope (no shrink, no creep)?
- Are your rejection findings actionable (specific file, section,
  fix)?

## Forbidden Content

- Do NOT include non-ASCII characters.
- Do NOT ask clarifying questions.
- Do NOT approve if critical issues exist.

Include APPROVED or REJECTED verdict prominently.

ASCII-only content.
