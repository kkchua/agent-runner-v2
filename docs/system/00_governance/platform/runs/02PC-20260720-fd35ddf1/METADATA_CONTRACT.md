## Additional Frontmatter Fields

The agent-runner-v2 platform adds these frontmatter fields beyond the
Layer 1 baseline.

### Platform-Specific Fields

| Field | Required | Description |
|---|---|---|
| `platform` | Yes (Layer 2 and 3 permanent docs) | Identifies the owning platform. Must be `"agent-runner-v2"` for documents on this platform. |
| `template_id` | Yes (permanent docs) | Stable template identifier used for structural validation. Format: `SYS-XX-XX` or `WF-XX-XX`. |
| `managed_by` | Conditional | For workflow-generated documents, indicates workflow management. Value `"workflow-generated"` signals that the document is protected from manual edits. |

### Field Placement

The `platform` field must appear in the YAML frontmatter of every Layer 2
platform standard and every Layer 3 permanent output. It enables scanners
to identify which platform owns a document without inspecting its content.

The `template_id` field provides a stable identifier for structural
validation. Each permanent document in a governed set has a unique
`template_id` (see the Platform Index document map for Layer 2 template
IDs).

The `managed_by` field is required for workflow-generated documents. Its
presence signals to human readers and automated systems that the document
is managed by a workflow and should not be edited manually.

### Field Conflicts

Layer 2 fields must not conflict with Layer 1 baseline fields. If a
platform-specific field were to share a name with a Layer 1 field, Layer 1
semantics take precedence. In practice, all platform-specific fields have
names distinct from the Layer 1 baseline.

## Inheritance Rules

### Downward Inheritance

Metadata rules inherit downward across layers:

1. **Layer 1 defines the baseline** : Field names (`doc_type`,
   `authority`, `scan_policy`, `scan_reason`) and their allowed values are
   defined by Layer 1.
2. **Layer 2 extends the baseline** : This platform adds fields
   (`platform`, `template_id`, `managed_by`) and refines the meaning of
   `bundle_definition` and `platform_standard` for the agent-runner-v2
   context.
3. **Layer 3 inherits Layer 1 + Layer 2** : Layer 3 bundles must use both
   Layer 1 baseline fields and Layer 2 platform extensions on all
   permanent outputs.

### What Layer 3 Must Do

- Include all Layer 1 required fields on permanent outputs
- Include the `platform` field with value `"agent-runner-v2"`
- Include a `template_id` for documents expecting structural validation
- Use `layer: "layer3"` on all Layer 3 permanent documents
- Use `bundle_definition` for bundle governance files, `workflow_output`
  for generated outputs

### What Layer 3 Must Not Do

- Redefine Layer 1 `doc_type` or `authority` vocabulary meanings
- Use `platform_standard` as `doc_type` (reserved for Layer 2 platform
  constitution documents)
- Claim `platform-owned` as `authority` (reserved for Layer 2 platform
  core)
- Omit the `platform` field on permanent outputs
- Use `layer: "layer1"` or `layer: "layer2"` on bundle outputs

### Promotion Rule

Documents do not become higher-layer authority merely because they are
useful or widely referenced. Promotion from Layer 3 to Layer 2 requires:

1. Explicit review against Layer 2 scope
2. Reclassification under Layer 2 metadata rules
3. Acceptance by the platform core owning authority

## Scan Policy Expectations

### Layer 2 Platform Standards

Layer 2 platform constitution documents carry:

- `scan_policy: "include"` : Included in all operational scans
- `scan_reason` explaining their role as permanent platform authority

### Layer 2 Evidence Artifacts

Review, validation, and audit artifacts generated during platform core
workflow runs carry:

- `scan_policy: "conditional"` or `"exclude"` : Excluded from normal
  operational scans
- `scan_reason` identifying them as temporary evidence

### Layer 3 Bundle Outputs

Layer 3 permanent outputs carry `scan_policy: "include"`. Layer 3 evidence
artifacts carry `scan_policy: "conditional"` or `"exclude"`.

### Scanner Compliance

All scanners, validators, and workflow components on this platform must:

1. Honor explicit `scan_policy` metadata when present
2. Skip documents with `scan_policy: "exclude"` unless explicitly targeted
3. Require explicit inclusion rules for `scan_policy: "conditional"`
4. Treat documents with absent or malformed metadata as non-compliant
5. Never assume authority solely because a document was discovered by a
   scan
