## Step 4: refine_sop ❌ (FAILED — BUG #1)
- **Coder:** claude-sonnet-4-6 (→ codex)
- **Duration:** ~171s (first attempt), ~90s (second attempt)
- **Status:** REJECTED → FAILED (exhausted max_rejects=2)
- **Error:** `MetaJsonInvalidError: meta.json at .../delivery_sop.meta.json is missing coder_result object`

### Root Cause Analysis:
When codex runs the refine step, it:
1. Successfully edits the SOP document ✅
2. **Overwrites the meta.json with a custom format** ❌

**What codex wrote (WRONG):**
```json
{
  "schema_version": "v2",
  "artifact": "delivery_sop.json",
  "last_updated": "2026-06-04",
  "refinement": "review feedback applied",
  "updated_files": ["..."],
  "review_source": "..."
}
```

**What it should have written (CORRECT):**
```json
{
  "schema_version": "v2",
  "coder_result": {
    "status": "APPROVED" | "REJECTED",
    "remark": "<summary>",
    "artifacts": {
      "DELIVERY_SOP": "<path>",
      "DELIVERY_STATUS_RULES": "<path>"
    },
    "recorded_at": "<ISO-8601>"
  }
}
```

### Why This Happens:
The refine prompt (`05_refine_sop.txt`) includes instructions about meta.json but codex is ignoring them and writing its own format. This is a **coder behavior issue** — the prompt instructions aren't strong enough to prevent codex from overwriting with its own format.

### Impact:
- The refine loop breaks completely
- Job status goes to FAILED (exhausted max_rejects)
- No auto-retry possible without manual intervention

### Fix Options:
1. **Make refine prompts stronger** — Add explicit "DO NOT use custom meta.json format" instruction
2. **Add post-processing validation** — After refine step completes, validate meta.json format and fix if needed
3. **Use a different coder for refine** — The refine_sop prompt already specifies `claude-sonnet-4-6` which resolves to codex. Could try qwen instead.
4. **Add meta.json protection** — Before refine step, backup meta.json; after refine, check if it was corrupted and restore + enrich
