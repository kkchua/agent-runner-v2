# Developer Guide: agent-runner-v2

## Development Workflow

### Getting Started

1. **Clone the repository**:
   ```bash
   git clone https://github.com/kkchua/agent-runner-v2.git
   cd agent-runner-v2
   ```

2. **Create virtual environment**:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate  # Windows
   pip install -e .
   ```

3. **Configure environment**:
   ```bash
   copy .env.example .env
   # Edit .env with your Pushover credentials (optional)
   ```

4. **Run bootstrap workflows**:
   ```bash
   run-init.bat
   run-00_layer1_governance_bootstrap_v1.bat
   run-00_repo_master_docs_bootstrap_v1.bat
   ```

## Documentation Responsibilities

### Codebase Documentation

Developers adding new modules must ensure:

1. **Module file**: Add Python file to appropriate location
2. **Module doc**: Documentation generated by `scan_repo_codebase` action
3. **Component doc**: Update component documentation if adding to existing component
4. **Change impact**: Document changes in `docs/repo/codebase/04_changes/`

### Workflow Documentation

Developers adding new workflows must:

1. **Create workflow package**: `agent_runner_v2/bootstrap/workflows/default/<workflow_name>/`
2. **Write workflow.toml**: Declarative manifest with steps, routing, artifact keys
3. **Write prompts**: `prompts/*.txt` files for each coder step
4. **Write actions.py**: Optional workflow-specific actions
5. **Write context_extensions.py**: Optional context hooks
6. **Register workflow**: Add to `_registry/` if using global deployment

### Governance Documentation

Developers modifying architecture must:

1. **Update constants.py**: Add new artifact keys and folder paths
2. **Update decision log**: Document architecture decisions
3. **Run bootstrap**: Regenerate governance docs after structural changes

| Attribute | Value |

| Target profile | Plugin-based workflow bundles |

### Migration Trajectory

- **From**: Monolithic `TEMPLATE_GROUPS` dict (2453 lines in `template_groups.py`)
- **To**: Self-contained plugin workflow packages with TOML manifests
- **Status**: Bootstrap workflows migrated; legacy SDLC workflows pending

### Layer Dependency Chain

The architecture follows a layered dependency model:

```
Layer 1: 00_layer1_governance_bootstrap_v1 → docs/system/00_governance/
    ↓ (required)
Layer 2: 00_repo_master_docs_bootstrap_v1 → docs/repo/governance/
    ↓ (required)
Layer 3+: SDLC workflow families → docs/repo/sdlc/
```

**Implication**: Layer 3+ workflows cannot run until Layer 2 is complete.

### Repo-Selected Profile

This repository follows the ecosystem baseline with one exception:

- **SDLC folder structure**: Adopted semantic folder structure (`docs/repo/sdlc/01_requirements/`, etc.) instead of delivery-centric naming
- **Reason**: AI-Driven SDLC research recommends phased architecture with semantic artifact ownership

## Development Standards

### Code Style

- Follow PEP 8 conventions
- Use type hints for public APIs
- Document public functions with docstrings
- Use raw strings for docstrings containing backslashes

### Module Organization

| Area | Purpose | Naming |
|------|---------|--------|
| `core` | Execution engine | `run_agent.py`, `step_runner.py`, `workflow_router.py` |
| `coder` | LLM integration | `coder_adapters.py`, `model_config.py` |
| `backend` | Backend client | `daemon.py`, `backend_client.py` |
| `actions` | Deterministic actions | `actions/*.py` |
| `support` | Utilities | `constants.py`, `notifications.py` |

### Testing Requirements

- Unit tests must be pure logic without filesystem dependencies
- Integration tests use `tests/integration/` with real files
- All tests use pytest with `unit` and `integration` markers
- Target: 100% pass rate on unit tests before merge

### Git Workflow

- Feature branches follow pattern: `feat/<feature-name>`
- Commits should reference workflow or issue when applicable
- Do not commit `.env`, `.venv/`, or agent-specific config files
