# Requirements Overview

This document defines the structured requirements for SDLC workflow input
handling in the operator console (Flet desktop GUI) for the initiative
intake workflow (sdlc_00_init_doc_v1). This is Phase 1 of an eight-phase
console SDLC support plan.

## Existing Implementation Context

Codebase inspection confirms that the dynamic input handling infrastructure
described in the source initiative already exists in the operator console:

- The file picker UI component (Flet FilePicker, read-only TextField, and
  Browse button) is already present in operator_console/app.py.
- The rebuild_input_fields() function dynamically generates input fields
  based on the selected workflow bundle definition (workflow.toml
  required_inputs).
- The SDLC_INPUT_DIRS mapping already maps artifact keys to delivery
  subdirectories.
- The runner_service.submit_job() method already accepts and forwards
  input_artifacts as --input KEY=VALUE arguments.
- The resolve_input_path() function handles path resolution for SDLC
  artifact keys.
- Conditional visibility logic already hides input fields when no workflow
  is selected.

Therefore, the requirements in this document are framed as verification
and validation requirements: they specify the behaviors that must be
confirmed working for the sdlc_00_init_doc_v1 workflow use case. No new
infrastructure is required; the initiative validates that the existing
infrastructure satisfies the SDLC Phase 1 workflow input scenario.

# Functional Requirements

## FR-001: Dynamic Input Field Generation for SDLC Workflows [Must]

The console must dynamically generate input fields when a workflow with
required_inputs is selected. For each required input artifact key ending
with "_FILE", a file picker row (read-only TextField plus Browse button)
must be displayed. For sdlc_00_init_doc_v1, the key DRAFT_INIT_FILE must
produce a file picker row.

The input fields are generated by reading the workflow bundle definition
(workflow.toml) via the init step name and its required_inputs list.

Priority: Must
Traceability: Initiative Section "Scope - In Scope" (wire the existing
file picker to the submit job action flow). Initiative Section "Expected
Outcomes" item 1.

## FR-002: Conditional Visibility of Input Field Rows [Must]

Input field rows must be visible only when the selected workflow has
required_inputs declared in its bundle definition. For sdlc_00_init_doc_v1,
the DRAFT_INIT_FILE row must appear when that workflow is selected.
For workflows without required_inputs, no input field rows must appear.

Additionally, input field rows should only be relevant when the action
is "Submit". When a non-submit action is selected, the action execution
controls take precedence and input fields may be hidden or disabled.

Priority: Must
Traceability: Initiative Section "Expected Outcomes" item 5, and Section
"Scope - In Scope" (conditional visibility).

## FR-003: Draft Initiative Document Selection via File Picker [Must]

Users must be able to browse and select a DRAFT_INIT_FILE (Markdown
format, .md extension) from the local filesystem through the file picker.
The Browse button must invoke the Flet FilePicker with file type filtering
for .md files. The selected file path must be displayed in the read-only
TextField for user confirmation.

If the user cancels the file picker dialog without selecting a file, the
TextField must retain its previous value (or remain empty if no file was
previously selected). No error must be displayed.

Priority: Must
Traceability: Initiative Section "Expected Outcomes" item 2.

## FR-004: Input Artifact Forwarding Through Service Layer [Must]

When the user clicks "Run Action" with "Submit" selected, the console
must collect all populated input field values and pass them as
input_artifacts to runner_service.submit_job(). The method must forward
each entry as --input KEY=VALUE arguments to submit_commands.main().
For Phase 1, the key must be DRAFT_INIT_FILE and the value must be the
absolute path of the selected file.

If no input fields have values, the submission must proceed without any
--input arguments (backward compatible with non-SDLC workflows).

Priority: Must
Traceability: Initiative Section "Expected Outcomes" item 3, and Section
"Scope - In Scope" (update runner_service.submit_job(), pass selected
file path).

## FR-005: SDLC Directory Resolution for File Picker [Should]

When the Browse button is clicked for a known SDLC input artifact key,
the console should attempt to set the file picker root directory to the
corresponding SDLC delivery subdirectory within the selected repository.
For DRAFT_INIT_FILE, this is
docs/repo/agent_runner/sdlc/delivery/00_draft_initiatives.

Note: The current implementation sets file_picker.root_directory before
calling pick_files() but does not pass initial_directory to pick_files().
The OS file dialog may not honor the root_directory attribute. This is
a known limitation (see RA-007).

Priority: Should
Traceability: Derived from initiative Section "Dependencies" (draft
initiative documents location) and codebase SDLC_INPUT_DIRS mapping.

## FR-006: Input Path Resolution [Must]

The console must resolve input field values to absolute file paths before
passing them to the submit command. If a value is a filename only (not
an absolute path), the console must resolve it relative to the known SDLC
delivery subdirectory for that artifact key (via SDLC_INPUT_DIRS mapping).
If the resolved file does not exist, an error must be reported to the
user and the submission must not proceed.

Priority: Must
Traceability: Derived from initiative Section "Success Criteria" and
codebase resolve_input_path() implementation.

## FR-007: Non-SDLC Workflow Submission Continuity [Must]

The console must continue to function correctly for all existing non-SDLC
workflows. Generic job submission (without file picker input) must work
without regression. No input artifact arguments shall be passed for
non-SDLC workflow submissions that have no required_inputs.

Priority: Must
Traceability: Initiative Section "Boundary Conditions" (console must
continue to function correctly for non-SDLC workflows) and Section
"Success Criteria" (non-SDLC submission regression).

## FR-008: Error Display for Input Resolution Failures [Must]

If the selected file does not exist or cannot be resolved to a valid
path, the console must display a clear error message indicating which
artifact key failed and the expected directory path. The error must be
shown via the existing output/error display mechanism. The submission
must not proceed until the error is resolved.

Priority: Must
Traceability: Derived from initiative Section "Success Criteria" and
codebase error handling patterns.

## FR-009: Architectural Extensibility for Future Phases [Should]

The dynamic input field mechanism must be generic per artifact key,
reading required_inputs from the workflow bundle definition. Phase 1
targets DRAFT_INIT_FILE exclusively, but the mechanism must accommodate
additional artifact keys (for example, INIT_FILE for sdlc_10, REQ_FILE
for sdlc_20) through the same code path without structural refactoring.

Priority: Should
Traceability: Initiative Section "Boundary Conditions" (extensible to
support different input artifact keys in future phases).

# Risk Assessment

## RA-001: File Picker root_directory Not Honored on Windows

- Risk: The existing code sets file_picker.root_directory before calling
  pick_files(), but pick_files() does not receive initial_directory as a
  parameter. The OS file dialog may open at the default directory (user
  home) rather than the SDLC delivery subdirectory.
- Severity: Medium
- Impact: Users may need to navigate manually to the draft initiatives
  directory each time. Functionality is not broken, but usability is
  reduced.
- Mitigation: In a future iteration, pass the resolved SDLC directory as
  initial_directory to pick_files(). For Phase 1, users can navigate
  manually. Document this limitation for operators.

## RA-002: Regression in Non-SDLC Workflow Submission

- Risk: Verification or changes to the submit flow may inadvertently
  affect non-SDLC workflow submissions by passing empty or incorrect
  input artifacts.
- Severity: High
- Mitigation: Verify that input_artifacts is only populated when dynamic
  input fields have values. Verify that non-SDLC workflows (which have
  no dynamic input fields) do not pass any --input arguments. Include
  regression test for non-SDLC submission (AC-008).

## RA-003: Future Phase Extensibility

- Risk: The Phase 1 validation may not uncover issues that arise when
  subsequent SDLC workflows (sdlc_10 through sdlc_80) introduce
  different input artifact types or multiple required inputs.
- Severity: Medium
- Mitigation: The dynamic input field mechanism (rebuild_input_fields)
  reads required_inputs from workflow.toml generically. The SDLC_INPUT_DIRS
  mapping already supports all known artifact keys. Test with multiple
  workflow configurations if possible.

## RA-004: Workflow Bundle Loading Failures

- Risk: The workflow package loader may fail to parse certain bundle
  definitions or the init step may not declare required_inputs correctly,
  causing the dynamic input panel to show errors or no fields.
- Severity: Medium
- Mitigation: The console handles bundle loading errors gracefully with
  error messages in the dynamic input panel. Maintain this error handling
  pattern. Verify that sdlc_00_init_doc_v1 workflow.toml is valid.

## RA-005: File Path Resolution Edge Cases

- Risk: File path resolution may fail for edge cases such as relative
  paths, paths with special characters, or paths that cross directory
  boundaries.
- Severity: Low
- Mitigation: Use Path objects for all path operations (existing pattern).
  Validate that resolved paths exist before submitting (AC-009). Provide
  clear error messages for unresolvable paths.

## RA-006: Flet API Version Drift

- Risk: The Flet library version may be updated, changing the FilePicker
  API (parameter names, return types, or callback patterns).
- Severity: Low
- Mitigation: Pin the Flet version in the console dependencies. Verify
  FilePicker API compatibility after any Flet version update. Current
  verified version: 0.86.1 with async pick_files() returning
  list[FilePickerFile] where each entry has a path attribute.

## RA-007: File Picker Cancellation and State Consistency

- Risk: If the user switches workflow while a file picker dialog is open,
  the selected file may be assigned to the wrong artifact key or the
  TextField may be updated for a workflow that is no longer selected.
- Severity: Low
- Mitigation: The existing code uses closure-captured key parameters for
  Browse button handlers (async def on_browse_click(e, k=key, f=tf)),
  which binds the artifact key and TextField reference at handler
  creation time. This prevents state conflicts when switching workflows.
