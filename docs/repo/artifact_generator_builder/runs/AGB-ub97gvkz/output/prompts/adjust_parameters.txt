## Step: adjust_parameters

## Role Policy

architect_standard

## Identity

- Codename: codebase_intelligence
- Generator: Codebase Intelligence Generator
- Version: 1.0.0
- Pattern: Input Transformation (Pattern 2)

## Task

You are adjusting the RuntimeConfig parameters for the codebase_intelligence
pipeline based on quality review feedback. This step is activated only when
the quality reviewer (Step 16: review_quality) has REJECTED the reports.

Your adjustments modify analysis thresholds and sensitivity levels so that
the re-execution of the analysis pipeline (Steps 7-15) produces better
quality findings.

## Input

- QUALITY_REVIEW_REPORT: Detailed feedback from the quality reviewer
  identifying specific quality issues.
- RUNTIME_CONFIG: Current configuration with dimension and phase settings.

## Adjustment Scope

You may modify the following RuntimeConfig parameters:

### Health Dimension Thresholds

| Parameter | Default | Adjustment Direction |
|---|---|---|
| DIM-COUPLING.fan_in_threshold | 10 | Lower to catch more, raise to reduce noise |
| DIM-COUPLING.fan_out_threshold | 15 | Lower to catch more, raise to reduce noise |
| DIM-COMPLEXITY.cyclomatic_threshold | 10 | Lower to catch more, raise to reduce noise |

### Security Phase Sensitivity

| Parameter | Adjustment Direction |
|---|---|
| PHASE-SECRETS enabled | Toggle on/off |
| PHASE-DEPS enabled | Toggle on/off |
| PHASE-CODEPAT enabled | Toggle on/off |
| PHASE-AUTH enabled | Toggle on/off |
| PHASE-INFRA enabled | Toggle on/off |

### Rules

1. Do NOT disable all dimensions or all phases (INV-022 requires 3+ output types)
2. Do NOT change the codename or identity
3. Keep adjustments proportional to the quality feedback
4. If evidence sufficiency is low: lower thresholds to catch more issues
5. If report is too noisy: raise thresholds to reduce low-value findings

## Output

Write the adjusted configuration to: {ADJUSTED_CONFIG}

The adjusted config MUST be a valid JSON file following the same schema
as the original RUNTIME_CONFIG.

After writing the adjusted config, the workflow re-executes from
Step 7 (analyze_audiences) through Step 15 (validate_outputs) with
the updated parameters.

## Constraints

- ASCII-only output
- Valid JSON configuration
- Do not remove enabled dimensions or phases that were active
- Do not invent new dimension or phase identifiers
