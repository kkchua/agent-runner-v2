# Objective

Adjust the RuntimeConfig parameters based on quality review feedback
to improve the summary output. This step is activated only when the
review_quality step rejects the summary for quality reasons.

Modify pipeline parameters such as relevance_threshold and
redundancy_threshold to produce a better summary on re-execution.

# Reference Inputs

- QUALITY_REVIEW_REPORT: {QUALITY_REVIEW_REPORT}
- RUNTIME_CONFIG_FILE: {RUNTIME_CONFIG_FILE}
- OUTPUT_METADATA_FILE: {OUTPUT_METADATA_FILE}
- DOC_STRUCTURE_FILE: {DOC_STRUCTURE_FILE}

# Adjustment Tasks

1. **Analyze Review Feedback**:
   - Read the QUALITY_REVIEW_REPORT to understand what aspects of
     the summary were inadequate.
   - Identify whether the issues relate to:
     a. Too many/too few key points selected
     b. Too much/too little redundancy removal
     c. Poor core message capture
     d. Structural ordering problems

2. **Adjust Relevance Threshold**:
   - If summary has too many key points and poor focus:
     Increase relevance_threshold (e.g., 0.5 -> 0.6 or 0.7)
   - If summary has too few key points and missing information:
     Decrease relevance_threshold (e.g., 0.5 -> 0.4 or 0.3)
   - Do not set below 0.1 or above 0.9

3. **Adjust Redundancy Threshold**:
   - If summary has repetitive content:
     Decrease redundancy_threshold (e.g., 0.8 -> 0.7)
     to cluster more aggressively
   - If summary lost distinct ideas due to over-clustering:
     Increase redundancy_threshold (e.g., 0.8 -> 0.9)
     to preserve more distinct keypoints
   - Do not set below 0.3 or above 0.99

4. **Preserve Other Parameters**:
   - Keep target_compression_ratio at 0.20 (C-001 constraint)
   - Keep output_type unchanged
   - Keep implementation names unchanged unless review specifically
     requests a different implementation

# Self-Critic

- Did I base adjustments on specific review feedback?
- Are the new parameter values within reasonable bounds?
- Did I preserve the compression constraint (0.20)?
- Are my changes likely to address the identified quality issues?

# Forbidden Content

- Do NOT change target_compression_ratio (hard constraint C-001)
- Do NOT change output_type
- Do NOT include non-ASCII characters
- Do NOT make changes without justification from the review report

# Output Instructions

Write to: {ADJUSTED_CONFIG}
JSON format containing the updated RuntimeConfig parameters.

The adjusted config must include:
- All parameters from the original RUNTIME_CONFIG_FILE
- Modified values for any adjusted parameters
- A "adjustment_reason" field explaining the changes

ASCII-only. No em-dashes or curly quotes.
