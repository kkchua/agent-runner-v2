# Objective

Generate the composition standard for the generated meta builder.
This is the key v3 innovation: every generated meta builder has its
own composition standard that defines its component types, composition
format, and output format across the 3-layer architecture.

This step produces the COMPOSITION_STANDARD_FILE.

## Reference Inputs

Read the following files before producing any output:

- WORKFLOW_SPEC_FILE: {WORKFLOW_SPEC_FILE}
  Read the target domain's requirements. The composition standard
  must define component types for this domain.

- TEST_CRITERIA_FILE: {TEST_CRITERIA_FILE}
  Read criteria for Phase 6 (Composition Standard).

- COMPONENT_SCHEMA_FILE: {COMPONENT_SCHEMA_FILE}
  Read the meta builder's component schema (Layer 1).

- COMPOSITION_FORMAT_FILE: {COMPOSITION_FORMAT_FILE}
  Read the meta builder's composition format (Layer 2).

- OUTPUT_FORMAT_FILE: {OUTPUT_FORMAT_FILE}
  Read the meta builder's output format (Layer 3).

- OPERATIONAL_WORKFLOW_FILE: {OPERATIONAL_WORKFLOW_FILE}
  Read the operational workflow design for step context.

## Generation Tasks

Produce a composition standard document (Standards/COMPOSITION_STANDARD.md)
with these sections:

1. **Overview** -- Standard name, version, domain context.

2. **Component Schema (Layer 1)** -- Component types for the target
   domain. Read types from WORKFLOW_SPEC_FILE.

3. **Composition Format (Layer 2)** -- Binding rules, override
   mechanism, placeholder resolution for the target domain.

4. **Output Format (Layer 3)** -- Output structure, resolution
   rules, quality requirements for the target domain.

5. **Self-Validation** -- Verify all 3 layers defined.

The standard must include:
- standard_name (from the spec)
- standard_version
- component_types_defined (from the spec's component types)
- schema_sections (exactly 3: Component Schema, Composition Format,
  Output Format)
- extensibility_model (concrete description)

## Self-Critic

- Did you read component types from the spec, not invent them?
- Are all 3 layers defined?
- Is the extensibility_model concrete, not vague?

## Forbidden Content

- Do NOT invent component types beyond what the spec defines.
- Do NOT include non-ASCII characters.
- Do NOT ask clarifying questions.

## Output Instructions

Use file-writing tools to write the composition standard to:
{COMPOSITION_STANDARD_FILE}

Format: Markdown with YAML frontmatter
Frontmatter must include:
  doc_type: "composition_standard"
  lifecycle_status: "draft"
  standard_name: (from spec)
  standard_version: (from spec)

ASCII-only content.

The result field in meta.json is for status summary ONLY.
