# Step: refine_output

## Objective

Fix all issues identified in the review report. Read the REVIEW_FILE_SUGGESTED
findings, address each one individually, and produce a corrected version of the
output file. This step only executes when the review step produces a REJECTED
verdict. Your corrections must be precise and traceable to specific review
findings.

This step preserves all content that was not flagged by the review. It does not
restructure or rewrite unflagged sections. Each fix must address a specific
finding from the review report.

## Reference Inputs

Read these files for context. Use ONLY information from these files.

- Review Report: {REVIEW_FILE_SUGGESTED}
  The structured review report with findings table. Each finding has a severity,
  check category, location, and description. Address EVERY finding.

- Current Output File: {OUTPUT_FILE}
  The output file that was reviewed. This is the file you will fix.

- Resolution Plan: {RESOLUTION_PLAN_FILE}
  The original composition resolution instructions, used to verify correct
  binding resolution, override application, and placeholder mapping.

- Component Inventory: {COMPONENT_INVENTORY_FILE}
  The component library inventory, used to verify correct component expansion.

- Data Source Directory: {DATA_SOURCE_DIR}
  Directory containing placeholder resolution data files, used to verify
  correct placeholder values.

## Fix Process

For each finding in the review report:

1. Identify the finding by its severity, check category, and location.
2. Determine the root cause (not just the symptom).
3. Apply the minimal fix needed to resolve the issue.
4. Record the fix in a fix log.

### Fix Categories

- Missing section: Add the missing section with correct content.
- Incorrect override: Replace the wrong value with the correct override value.
- Unflagged placeholder: Replace raw {placeholder} with either the resolved
  value or {UNRESOLVED: placeholder_name}.
- Cross-section contradiction: Align the conflicting values across sections.
- Frontmatter error: Correct the incorrect metadata field.
- Duration calculation error: Recalculate and update the duration summary.
- Missing transition directive: Insert the correct transition between scenes.

### Constraints

- Do NOT change content that was not flagged by the review.
- Maintain cross-section consistency after all fixes are applied.
- Preserve all fixes from prior iterations (cumulative refinement).
- Each fix must trace to a specific finding in the review report.

## Output Instructions

Write the corrected output file to {OUTPUT_FILE}, overwriting the previous
version. The corrected file must have the same structure as the original
(markdown with YAML frontmatter and all required sections).

After the corrected output, include a Fix Log as an HTML comment block at the
end of the file:

```
<!-- Fix Log:
Finding 1: [severity] [check] [location] -> Fix applied: [description]
Finding 2: [severity] [check] [location] -> Fix applied: [description]
...
-->
```

## File Writing Instructions

CRITICAL: You MUST use file-writing tools to write the corrected output file
to disk at the path specified by {OUTPUT_FILE}. Do NOT print the content as
your response. Write it to the file using write_file or create_file tools.

The output file must be complete. Do not use "..." or "TODO" or "remaining
sections as above" as substitutes for actual content. Every section must
contain its full content.

Use ASCII characters only. Do not use em-dashes, curly quotes, or Unicode
symbols.

## meta.json Instructions

After writing the corrected output file, write the meta.json sidecar. The
result field in meta.json is for status summary ONLY -- it is NOT for artifact
data. The artifacts dict must map OUTPUT_FILE to the absolute path of the
corrected file you wrote.

## Self-Critic

Before completing, verify:
1. EVERY finding from the review report has been addressed.
2. No new issues were introduced by the fixes.
3. Cross-section consistency is maintained after all fixes.
4. The fix log documents each fix with its corresponding finding.
5. All placeholders are resolved or flagged as {UNRESOLVED: field_name}.
6. YAML frontmatter fields are correct after fixes (especially
   unresolved_placeholder_count and lifecycle_status).
7. component_count is accurate after any structural changes.
8. The output file was written to disk, not just described.
9. Content that was NOT flagged by the review remains unchanged.

Re-read the corrected output file after writing and confirm it addresses
all review findings.
