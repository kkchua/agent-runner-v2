# Objective

Gatekeep review of the operational workflow design. Validate that it
correctly defines all 9 phases, 21 steps, valid routing, complete
artifact flow, and correct action specifications. Produce APPROVED
or REJECTED verdict.

This step produces the GATEKEEP_OPERATIONAL_WORKFLOW_FILE.

## Reference Inputs

Read the following files before producing any output:

- OPERATIONAL_WORKFLOW_FILE: {OPERATIONAL_WORKFLOW_FILE}
  Validate the complete operational workflow document.

## Validation Checklist

1. **Phase count** -- Exactly 9 phases defined.
2. **Step count** -- Exactly 21 steps defined (18 prompt, 3 action).
3. **Step routing** -- Every non-terminal step has valid onsuccess.
   No dangling references.
4. **Artifact flow** -- Every required_inputs references an artifact
   produced by a prior step or declared as input.
5. **Review loops** -- 8 loops with correct properties (step, artifact,
   max_iterations, exhausted_failure_code, exhausted_failure_class).
6. **Action specs** -- validate_package_deterministic,
   promote_workflow_package, step_completion all documented.
7. **Type classification** -- All deterministic ops are action steps.
   All LLM-judgment tasks are prompt steps.
8. **Package inventory** -- All files listed with correct categories.

## Decision Rules

Return APPROVED if all checklist items pass.
Return REJECTED with specific findings.

## Self-Critic

- Did you verify step routing by tracing every onsuccess target?
- Did you check artifact flow by building the cumulative produced set?

Format: Markdown with YAML frontmatter.
Include APPROVED or REJECTED verdict.

ASCII-only content.
