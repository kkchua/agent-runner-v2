# Objective

Generate the meta composition spec for self-bootstrapping. This is
a v3 innovation: the spec defines component types, composition rules,
and output structure in a format that can be fed as input to the
generated meta builder, enabling self-bootstrapping capability.

This step produces the META_COMPOSITION_SPEC_FILE.

## Reference Inputs

Read the following files before producing any output:

- WORKFLOW_SPEC_FILE: {WORKFLOW_SPEC_FILE}
  Read the original specification for the target domain.

- TEST_CRITERIA_FILE: {TEST_CRITERIA_FILE}
  Read criteria for Phase 7 (Meta Composition Spec).

- COMPONENT_SCHEMA_FILE: {COMPONENT_SCHEMA_FILE}
  Read the component schema (Layer 1).

- COMPOSITION_FORMAT_FILE: {COMPOSITION_FORMAT_FILE}
  Read the composition format (Layer 2).

- OUTPUT_FORMAT_FILE: {OUTPUT_FORMAT_FILE}
  Read the output format (Layer 3).

- OPERATIONAL_WORKFLOW_FILE: {OPERATIONAL_WORKFLOW_FILE}
  Read the operational workflow for step context.

- COMPOSITION_STANDARD_FILE: {COMPOSITION_STANDARD_FILE}
  Read the composition standard (v3 output).

## Generation Tasks

Produce a meta composition spec document with these 5 sections:

1. **Domain Overview** -- Target domain description, builder purpose,
   workflow pattern type.

2. **Component Schema** -- Component types for the target domain,
   extracted from the composition standard's Layer 1.

3. **Composition Format** -- Binding rules, override mechanism,
   placeholder resolution for the target domain.

4. **Output Format** -- Output structure, resolution rules, quality
   requirements for the target domain.

5. **Operational Requirements** -- Step sequence, artifact contracts,
   routing, action specifications.

The spec must be self-contained: a downstream workflow should be able
to use this single document as input to the generated meta builder
without needing any other artifacts.

## Self-Critic

- Is the spec self-contained and processable by the generated meta
  builder?
- Did you extract component types from the composition standard,
  not invent them?
- Are all 5 required sections present?

## Forbidden Content

- Do NOT include non-ASCII characters.
- Do NOT ask clarifying questions.
- Do NOT invent content beyond what the prior artifacts define.

## Output Instructions

Use file-writing tools to write the meta composition spec to:
{META_COMPOSITION_SPEC_FILE}

Format: Markdown with YAML frontmatter
Frontmatter must include:
  doc_type: "meta_composition_spec"
  lifecycle_status: "draft"
  domain: (target domain name)
  self_bootstrap_capable: true

ASCII-only content.

The result field in meta.json is for status summary ONLY.
