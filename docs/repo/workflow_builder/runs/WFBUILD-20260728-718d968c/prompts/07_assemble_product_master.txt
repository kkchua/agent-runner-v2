Objective

Assemble all section artifacts into the canonical Product Master document.
This is the integration step where all independently generated sections
come together into a single cohesive document with YAML frontmatter,
table of contents, logical section ordering, deduplication, cross-
references, and source attribution.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2
  platform contract.
- Generate only the assembled Product Master document. Do not modify
  the individual section artifacts.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only
  reference inputs.

Reference Inputs

- Read ALL section artifacts:
  - Product Information: {PRODUCT_INFO_FILE}
  - Target Audience: {TARGET_AUDIENCE_FILE}
  - Benefits/USP: {PRODUCT_BENEFITS_FILE}
  - Marketing Assets: {MARKETING_ASSETS_FILE}
  - Additional Sections: {ADDITIONAL_SECTIONS_FILE}
- If provided, read the existing Product Master for incremental update:
  {PRODUCT_MASTER_FILE}
- Read the scan report for source file inventory:
  {SCAN_REPORT_FILE}
- Read Layer 1 governance documents for metadata standards:
  {GOVERNANCE_RUNTIME_ROOT}

Assembly Instructions

1. YAML Frontmatter (REQUIRED - first lines of the document):
   Include exactly these fields:
   - product_name: Name of the product (string, extracted from section
     content)
   - version: Version identifier for the Product Master (string, use
     date-based format YYYYMMDD-NN)
   - source_count: Number of source files processed (integer, from scan
     report summary)
   - completeness_rating: Assessment of knowledge coverage (one of:
     "comprehensive", "substantial", "partial", "minimal")

2. Table of Contents:
   Generate a table of contents listing all sections with heading anchors.

3. Section Order:
   Arrange sections in this logical order:
   a. Product Information
   b. Target Audience
   c. Benefits/USP
   d. Marketing Assets
   e. Additional Sections (if any were proposed; include even if stub)

4. Deduplication:
   If the same information appears in multiple section artifacts,
   consolidate it into the most appropriate section and add a cross-
   reference from the other section. Do not silently drop duplicate
   content.

5. Cross-References:
   Add cross-references between sections where content is related.
   Example: "See Target Audience for buyer persona details relevant
   to this benefit."

6. Source Attribution:
   Include a Source Attribution section that maps claims and data points
   to their originating source files (as listed in the scan report).

7. Incremental Update (Changelog):
   If {PRODUCT_MASTER_FILE} was provided as an optional input (meaning
   an existing Product Master exists), compare the new assembled content
   against the existing document and add a Changelog section recording
   what changed. The Changelog should include:
   - Date of update
   - Sections modified
   - Summary of changes (added, updated, removed content)
   If no existing Product Master was provided (fresh generation), do
   NOT include a Changelog section.

8. Section Completeness:
   Include ALL section artifacts in the assembled document. If a section
   is empty or a stub (e.g., Additional Sections has no proposals),
   include it with a note indicating the section contains no substantive
   content. Do not silently omit any section.

Output Instructions

- Write the assembled Product Master to the file at {PRODUCT_MASTER_FILE}.
- Use markdown format with YAML frontmatter as the first lines.
- The output file must be ASCII-only (no em-dashes, curly quotes, or
  other Unicode characters).
- Use plain text section headings without formatting markup in heading
  lines.
- Use the product slug ({SLUG}) to identify the product context.
- The result field in meta.json must contain a brief summary of what
  was assembled. All document content must be written to the artifact
  file, not placed in the meta.json result field.

Forbidden Content

- Campaign execution plans, media schedules, or marketing deployment
- Content not present in any section artifact
- Fabricated data not traceable to source files
- Sections silently omitted or dropped
