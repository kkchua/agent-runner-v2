Objective

Generate the Product Information section artifact for the Product Master.
This section covers factual product data extracted from the available
source materials.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2
  platform contract.
- Generate only the Product Information section content. Do not generate
  Target Audience, Benefits, Marketing Assets, or Additional Sections.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only
  reference inputs.

Reference Inputs

- Read the scan report to understand what source files are available:
  {SCAN_REPORT_FILE}
- Read the source directory for available product materials:
  {PRODUCT_SOURCE_DIR}
- Read Layer 1 governance documents for metadata standards:
  {GOVERNANCE_RUNTIME_ROOT}

Content Scope

Extract and document the following factual product data from the available
source files. This section covers ONLY factual and technical product data.
Do not include audience analysis, benefits, marketing content, or proposed
additional sections.

Required content domains:
- Product name, manufacturer, brand
- Model number, SKU, UPC/EAN
- Dimensions (L x W x H) and weight
- Materials and construction details
- Technical specifications (use structured tables where possible)
- Package contents
- Certifications and compliance information

Source File Guidance

Consult the scan report to determine which source files are available.
Source types may include: images (*.png, *.jpg, *.jpeg, *.webp, *.gif,
*.bmp), manuals (PDFs with manual/guide/user-guide in filename),
specifications (PDFs with spec/specification/datasheet in filename, or
CSV/XLSX/XLS files), documents (other PDFs, DOCX, DOC), and URL lists
(text files containing URLs).

For URL lists, use the webfetch tool to retrieve and read URL content.
Not all source types will be present in every product source directory.
Work only with the files that exist.

Knowledge Gap Handling

If information for a required content domain is not found in any source
file, represent it explicitly as a knowledge gap. Use the format:

  Not available from provided sources.

Do not fabricate or guess product data. Factual accuracy takes priority
over completeness.

Conflict Handling

If conflicting information is found across different source files,
explicitly note both sides with source attribution. Example:

  Product weight: 1.2 kg (per spec sheet) vs 1.5 kg (per marketing
  brochure). Discrepancy unresolved.

Output Instructions

- Write the generated content to the file at {PRODUCT_INFO_FILE}.
- Use markdown format with a section heading.
- The output file must be ASCII-only (no em-dashes, curly quotes, or
  other Unicode characters).
- Use plain text section headings without formatting markup.
- Use the product slug ({SLUG}) to identify the product context.
- The result field in meta.json must contain a brief summary of what
  was generated. All document content must be written to the artifact
  file, not placed in the meta.json result field.

Forbidden Content

- Audience analysis or buyer persona information
- Benefits or value proposition content
- Marketing campaign suggestions
- Additional section proposals
- Content not traceable to source files
