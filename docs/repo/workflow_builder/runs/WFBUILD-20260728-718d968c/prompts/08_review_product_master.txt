Objective

Review the assembled Product Master document for quality, factual
accuracy, completeness, source attribution, and structural coherence.
Produce a review critique document that evaluates the Product Master
against defined quality criteria.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2
  platform contract.
- Generate only the review critique document. Do not modify the Product
  Master.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only
  reference inputs.

Reference Inputs

- Read the assembled Product Master: {PRODUCT_MASTER_FILE}
- Read the scan report for source file inventory: {SCAN_REPORT_FILE}
- Read Layer 1 governance documents for metadata standards:
  {GOVERNANCE_RUNTIME_ROOT}

Evaluation Criteria

Evaluate the Product Master against each of the following criteria.
For each criterion, provide a judgment (Pass, Fail, or Partial) with
specific findings.

1. Factual Accuracy:
   - Are all product claims supported by source files?
   - Are there any fabricated data points or unsupported assertions?
   - Are conflicting sources properly noted with attribution?

2. Source Attribution:
   - Does the Source Attribution section map claims to their originating
     source files from the scan report?
   - Are there claims without source references?
   - Are source file paths accurate (matching the scan report)?

3. Completeness:
   - Does the Product Information section cover all required domains
     (name, manufacturer, model, SKU, dimensions, weight, materials,
     specs, package contents, certifications)?
   - Does the Target Audience section cover all required domains
     (demographics, personas, use cases, market segment, psychographics)?
   - Does the Benefits/USP section cover all required domains
     (value proposition, functional/emotional/social benefits, problems
     solved, differentiators)?
   - Does the Marketing Assets section cover all required domains
     (brand assets, visual inventory, trending topics, social hooks,
     campaign themes, influencer angles)?
   - Is the Additional Sections section present (even if a stub)?

4. Knowledge Gap Handling:
   - Are missing information items represented as explicit knowledge gaps?
   - Are there any gaps that were silently omitted instead of noted?

5. Structural Coherence:
   - Is the YAML frontmatter complete with all required fields
     (product_name, version, source_count, completeness_rating)?
   - Is the table of contents present and accurate?
   - Are sections in the correct logical order?
   - Are cross-references between sections appropriate?
   - Is deduplication handled correctly?

6. Incremental Update (if applicable):
   - If a Changelog section is present, does it accurately reflect
     changes from the prior Product Master?
   - If no prior Product Master was provided, is the Changelog
     correctly absent?

Overall Judgment

Provide an overall judgment:
- APPROVED: The Product Master meets all quality criteria and is ready
  for delivery.
- REJECTED: The Product Master has significant issues that require
  correction. List the specific issues and recommended fixes.

Output Instructions

- Write the review critique to the file at {REVIEW_FILE_SUGGESTED}.
- Use markdown format with a structured evaluation layout.
- The output file must be ASCII-only (no em-dashes, curly quotes, or
  other Unicode characters).
- Use plain text section headings without formatting markup.
- The result field in meta.json must contain a brief summary of the
  review outcome (APPROVED or REJECTED with issue count). All review
  content must be written to the artifact file, not placed in the
  meta.json result field.

Forbidden Content

- Rewriting or modifying the Product Master content
- Adding new product data not present in the source files
- Campaign execution or marketing deployment suggestions
