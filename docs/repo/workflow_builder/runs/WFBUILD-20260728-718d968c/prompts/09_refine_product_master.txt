Objective

Refine the Product Master document based on the review critique. Read
the review feedback and apply corrections to the Product Master in place.
The refined document replaces the current Product Master at the same
file path.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2
  platform contract.
- Modify only the Product Master document. Do not modify section
  artifacts or the review critique.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only
  reference inputs.

Reference Inputs

- Read the current Product Master to be refined: {PRODUCT_MASTER_FILE}
- Read the review critique for specific findings and recommendations:
  {REVIEW_FILE_SUGGESTED}
- Read the scan report for source file inventory if needed for
  verification: {SCAN_REPORT_FILE}
- Read Layer 1 governance documents for metadata standards:
  {GOVERNANCE_RUNTIME_ROOT}

Refinement Instructions

For each finding in the review critique, apply the appropriate correction:

1. Factual Corrections:
   - If the review identifies fabricated data, remove it and replace
     with an explicit knowledge gap marker: "Not available from provided
     sources."
   - If the review identifies unsupported claims, add source attribution
     or mark as unverified.
   - If the review identifies conflicting information, ensure both sides
     are noted with source attribution.

2. Missing Section Content:
   - If the review identifies a missing required content domain within
     a section, add a knowledge gap marker if the source files do not
     contain the information. Do not fabricate content.

3. Formatting Fixes:
   - If the review identifies YAML frontmatter issues, correct the
     frontmatter fields to match the required format:
     product_name (string), version (string), source_count (integer),
     completeness_rating (string).
   - If the table of contents is missing or inaccurate, regenerate it.
   - If section ordering is incorrect, reorder to: Product Information,
     Target Audience, Benefits/USP, Marketing Assets, Additional Sections.

4. Source Attribution Fixes:
   - If source attribution is missing for claims, add references to
     the originating source files from the scan report.
   - If source file paths are inaccurate, correct them.

5. Cross-Reference and Deduplication Fixes:
   - If duplicate content exists across sections, consolidate it and
     add cross-references.
   - If cross-references are missing, add them where sections are
     related.

6. Changelog Fixes (if applicable):
   - If the Changelog is present but inaccurate, correct it to match
     the actual changes from the prior Product Master.

In-Place Update

- Write the refined Product Master back to {PRODUCT_MASTER_FILE}.
- The output replaces the current file at the same path.
- The refined document must be a complete, standalone Product Master
  (not a diff or patch).
- Preserve all content that was not flagged by the review.

Output Instructions

- Write the refined Product Master to the file at {PRODUCT_MASTER_FILE}
  (same path as the input, replacing it in place).
- Use markdown format with YAML frontmatter as the first lines.
- The output file must be ASCII-only (no em-dashes, curly quotes, or
  other Unicode characters).
- Use plain text section headings without formatting markup.
- The result field in meta.json must contain a brief summary of what
  was corrected. All document content must be written to the artifact
  file, not placed in the meta.json result field.

Forbidden Content

- Campaign execution plans or marketing deployment strategies
- Fabricated data not traceable to source files
- Sections silently omitted or dropped
- Changes to section artifacts (PRODUCT_INFO_FILE, etc.)
