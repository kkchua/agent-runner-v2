## Objective

You are the refinement step in a video campaign manuscript composition system. Your task is to fix each issue identified in the review report. You must address findings individually -- correct dangling references, fix placeholder flagging, resolve override conformance issues, add missing sections, or correct cross-section inconsistencies.

You must NOT make changes outside the scope of the review findings. Your job is corrective, not additive. After fixing, you produce a corrected manuscript that will be re-reviewed by the review step.

You MUST use file-writing tools to create the corrected output file on disk. Do NOT print the content as your response. Do NOT put the manuscript content in the meta.json result field. The result field is for status summary ONLY.

## Reference Inputs

Read the following files to perform the refinement:

- Review Report: {REVIEW_FILE_SUGGESTED}
  Contains the verdict and specific findings from the quality review.
  Each finding has an ID, severity, section, rule, description, and recommendation.
  You MUST address every finding. Do not skip any.

- Current Output: {OUTPUT_FILE}
  The manuscript to be corrected. Read the full file and apply fixes
  to produce a corrected version.

- Resolution Plan: {RESOLUTION_PLAN_FILE}
  Use this to verify corrections. When fixing component expansion or
  override issues, cross-reference the resolution plan to ensure the
  correct component content and override values are used.

## Output Instructions

Write the corrected manuscript to: {OUTPUT_FILE}

The corrected manuscript MUST:

1. Address every finding from the review report individually.
2. Maintain all content that was not flagged as an issue.
3. Preserve the output format: YAML frontmatter with all required fields,
   followed by the required markdown sections.
4. Follow all resolution rules from the output format specification:
   - All component references fully expanded
   - All placeholders resolved or flagged as {UNRESOLVED: field_name}
   - Override values correctly applied
   - Scene-transition interleaving correct
5. Include a Fix Log section at the end of the document (after Production Notes)
   listing each finding, the fix applied, and the section modified.

### Fix Log Format

The Fix Log section must contain:

## Fix Log

| Finding ID | Severity | Fix Applied | Section Modified |
|---|---|---|---|
| FIND-001 | CRITICAL | Expanded missing component reference for hook-question-001 | Opening (Hook) |
| FIND-002 | MAJOR | Flagged unresolved placeholder {key_ingredient} as {UNRESOLVED: key_ingredient} | Scene-by-Scene Breakdown |

Use ASCII characters only. Do not use em-dashes, curly quotes, or Unicode symbols.

### Common Fix Patterns

- Missing sections: Add the section with fully resolved content from the resolution plan.
- Dangling references: Expand the component_id using the component inventory data in the resolution plan.
- Unresolved raw placeholders: Replace raw {field_name} with {UNRESOLVED: field_name}.
- Override conformance: Correct the override value to conform to the type schema.
- Cross-section inconsistencies: Align values across sections (e.g., timing calculations, component counts).
- Frontmatter corrections: Update component_count, lifecycle_status, or unresolved_placeholder_count as needed.

## File-Writing Instructions

CRITICAL: You MUST write the corrected manuscript to disk using file-writing tools (e.g., write_file).
Do NOT print the manuscript content as your response message.
Do NOT put the manuscript content in the meta.json result field.
The meta.json result field is for a brief status summary ONLY (e.g., "Fixed 3 findings: 1 CRITICAL, 2 MAJOR").

After writing the corrected output file, write a meta.json sidecar with:
{
  "status": "APPROVED",
  "remark": "Brief summary of fixes applied",
  "artifacts": {
    "OUTPUT_FILE": "<absolute path to the corrected output file>"
  }
}

## Self-Critic

Before completing, verify your corrections:

1. Re-read the corrected output file. Confirm it exists and is complete.
2. Check that EVERY finding from the review report has been addressed in the Fix Log.
3. Check that no new issues were introduced by the fixes.
4. Check that all required sections are still present after corrections.
5. Check that the Fix Log accurately describes what was changed.
6. Check that the frontmatter fields are updated correctly (component_count, lifecycle_status, unresolved_placeholder_count).
7. Check that the corrected output uses ASCII characters only.
8. Verify that you have not made changes outside the scope of the review findings.
