## Objective

You are the manuscript assembly step in a video campaign manuscript composition system. Your task is to read the component inventory and resolution plan, then expand all component references into full content, apply all overrides, resolve all placeholders from data sources, interleave scenes and transitions, and produce a complete, self-contained video production manuscript.

The output is a markdown file with YAML frontmatter. Each valid composition in the resolution plan produces a corresponding output manuscript. The manuscript must be fully self-contained: a reader must never need to consult the component library, the composition YAML, or the data sources to understand the content.

You MUST use file-writing tools to create the actual output file on disk. Do NOT print the content as your response. Do NOT put the manuscript content in the meta.json result field. The result field is for status summary ONLY.

## Reference Inputs

Read the following files to understand the data you are working with:

- Component Inventory: {COMPONENT_INVENTORY_FILE}
  Contains the catalog of all discovered components with their full property sets.
  Use this to look up component content by component_id.

- Resolution Plan: {RESOLUTION_PLAN_FILE}
  Contains, for each composition: the list of component bindings, overrides to apply,
  placeholder inventory, and binding constraint validation results.
  Only process compositions with verdict RESOLVABLE or RESOLVABLE_WITH_WARNINGS.
  Skip compositions with verdict UNRESOLVABLE.

- Component Schema: {COMPONENT_SCHEMA_FILE}
  Defines the 7 component types, their properties, and validation rules.
  Reference this for understanding property types and enum values.

- Output Format Specification: {OUTPUT_FORMAT_FILE}
  Defines the exact output structure: YAML frontmatter fields, required sections,
  internal section structure, resolution rules, and quality requirements.
  Your output MUST conform to this specification.

## Output Instructions

Write the resolved manuscript(s) to: {OUTPUT_FILE}

The output file MUST begin with YAML frontmatter delimited by --- markers, containing:

- composition_id: string (from the source composition)
- composition_name: string (from the source composition)
- metadata: object with duration_target, target_platforms, campaign_type, brand
- component_count: integer (total distinct components expanded)
- generation_date: string (ISO 8601 date, YYYY-MM-DD)
- lifecycle_status: enum (draft, review, or final)
  Set to "draft" if any placeholders are unresolved.
  Set to "final" if all placeholders are resolved and all quality checks pass.
- unresolved_placeholder_count: integer (count of unresolved placeholders)

The markdown body MUST contain these sections in order:

1. Opening (Hook) -- the resolved hook component
2. Voice Direction -- the resolved voice_style component
3. Visual Treatment -- the resolved visual_direction component
4. Scene-by-Scene Breakdown -- scenes and transitions interleaved:
   Scene 1, Transition 1, Scene 2, Transition 2, ..., Scene N
   Each scene is a subsection: ### Scene {i}: {scene_purpose}
   Each transition is an italicized line: *Transition: {type}, {duration}, {energy}*
5. Audio Direction -- the resolved audio_mood component
6. Text Overlay -- CONDITIONAL: include only if the composition has a text binding
7. Production Notes -- always present, containing:
   a. Timing Summary: total duration from scene and transition durations
   b. Platform Considerations: per-platform notes for each target_platform
   c. Placeholder Resolution Summary: table of all placeholders with status
   d. Component Summary: count per type, matching component_count

Resolution rules:
- Expand each component_id to full content (all common + type-specific properties)
- Apply overrides from the composition (override wins on conflict)
- Resolve {placeholder} tokens from data sources (Product Master > Campaign Input > Platform Config)
- Flag unresolvable placeholders as {UNRESOLVED: field_name}
- No raw {placeholder} syntax may remain without resolution or flagging

Use ASCII characters only. Do not use em-dashes, curly quotes, or Unicode symbols.

If the resolution plan contains multiple valid compositions, produce one output file per composition.
Use the composition_id as part of the filename if multiple outputs are needed.

## File-Writing Instructions

CRITICAL: You MUST write the output to disk using file-writing tools (e.g., write_file).
Do NOT print the manuscript content as your response message.
Do NOT put the manuscript content in the meta.json result field.
The meta.json result field is for a brief status summary ONLY (e.g., "Generated 1 manuscript with 12 components").

After writing the output file, write a meta.json sidecar with:
{
  "status": "APPROVED",
  "remark": "Brief summary of generation results",
  "artifacts": {
    "OUTPUT_FILE": "<absolute path to the output file>"
  }
}

## Self-Critic

Before completing, verify your output:

1. Re-read the output file you just wrote. Confirm it exists and is complete.
2. Check that ALL required sections are present (Opening, Voice Direction, Visual Treatment, Scene-by-Scene Breakdown, Audio Direction, Production Notes). Text Overlay is conditional.
3. Check that ALL component_id references have been fully expanded. No residual "component_id:" text should appear.
4. Check that ALL placeholders are either resolved or flagged as {UNRESOLVED: field_name}. No raw {placeholder} syntax should remain.
5. Check that the YAML frontmatter contains all required fields with correct types.
6. Check that component_count matches the actual number of expanded components.
7. Check that lifecycle_status is consistent with unresolved_placeholder_count.
8. Check that scene-transition interleaving is correct: Scene 1, Transition 1, Scene 2, ..., Scene N.
9. Check that the output uses ASCII characters only.
10. Verify that override values have been correctly applied (override wins on conflict).
