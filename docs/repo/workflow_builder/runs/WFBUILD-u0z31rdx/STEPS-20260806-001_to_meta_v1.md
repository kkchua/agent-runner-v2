# Step Architecture: Codebase to Meta Content v1

## Step Sequence

1. scan_audiences -- action -- (no role policy, action-driven)
2. generate_meta -- prompt -- architect_standard
3. review_meta -- prompt -- reviewer_standard
4. refine_meta -- prompt -- architect_standard
5. validate_meta -- action -- (no role policy, action-driven)
6. create_meta_backup -- action -- (no role policy, action-driven)
7. publish_meta -- action -- (no role policy, action-driven)
8. step_completion -- action -- step_completion shared action (terminal)

init_step: scan_audiences

## Step Details

### Step 1: scan_audiences

- **Name:** scan_audiences
- **Type:** action
- **Action function:** scan_audiences (from workflows/codebase_to_meta_v1/actions.py)
- **Prompt file:** N/A (action-driven)
- **Role policy:** N/A (action-driven)

**Artifact Bindings:**

| Binding | Value |
|---|---|
| required_inputs | (none -- reads filesystem directly) |
| produces | AUDIENCE_INDEX |
| result_meta_key | AUDIENCE_INDEX |

**Routing Rules:**

| Route | Target |
|---|---|
| onsuccess | generate_meta |

**Purpose:** Dynamically discover audience definition files from the workflow package audiences/ directory. Parse each .md file YAML frontmatter to extract audience_id, label, tone, focus_areas, exclude, and section_structure. Produce a JSON index of all discovered audiences for downstream steps.

---

### Step 2: generate_meta

- **Name:** generate_meta
- **Type:** prompt
- **Prompt file:** prompts/02_generate_meta.txt
- **Role policy:** architect_standard

**Artifact Bindings:**

| Binding | Value |
|---|---|
| required_inputs | CODEBASE_MANIFEST, AUDIENCE_INDEX |
| produces | META_DEV_FILE, META_ARCH_FILE, META_EXEC_FILE, META_INDEX |
| result_meta_key | META_INDEX |

**Routing Rules:**

| Route | Target |
|---|---|
| onsuccess | review_meta |

**Purpose:** Read the codebase documentation via CODEBASE_MANIFEST inventory and selectively read docs from each section. For each audience in the AUDIENCE_INDEX, generate a Rich Markdown meta content file tailored to that audience's tone, focus_areas, exclude list, and section_structure. Also produce a META_INDEX JSON file mapping each audience to its generated file path and metadata.

---

### Step 3: review_meta

- **Name:** review_meta
- **Type:** prompt
- **Prompt file:** prompts/03_review_meta.txt
- **Role policy:** reviewer_standard

**Artifact Bindings:**

| Binding | Value |
|---|---|
| required_inputs | META_DEV_FILE, META_ARCH_FILE, META_EXEC_FILE, META_INDEX, AUDIENCE_INDEX |
| produces | REVIEW_FILE_SUGGESTED |
| result_meta_key | REVIEW_FILE_SUGGESTED |

**Routing Rules:**

| Route | Target |
|---|---|
| onsuccess | validate_meta |
| on_reject_refine | refine_meta |

**Human Gate:** requires_human_approval_after = true

**Refinement Loop Configuration:**

| Property | Value |
|---|---|
| refine_step | refine_meta |
| artifact | META_INDEX |
| max_iterations | 2 |
| exhausted_failure_code | REFINE_EXHAUSTED |
| exhausted_failure_class | HUMAN_RETRY_REQUIRED |

**Purpose:** Review all generated meta content files for completeness, accuracy, audience-appropriateness, and structural compliance. The reviewer checks each file against its audience definition section_structure, tone, focus_areas, and exclude constraints. Produces a consolidated review document with feedback per audience.

---

### Step 4: refine_meta

- **Name:** refine_meta
- **Type:** prompt
- **Prompt file:** prompts/04_refine_meta.txt
- **Role policy:** architect_standard

**Artifact Bindings:**

| Binding | Value |
|---|---|
| required_inputs | META_DEV_FILE, META_ARCH_FILE, META_EXEC_FILE, META_INDEX, AUDIENCE_INDEX, REVIEW_FILE_SUGGESTED |
| produces | META_DEV_FILE, META_ARCH_FILE, META_EXEC_FILE, META_INDEX |
| result_meta_key | META_INDEX |
| target_artifact | META_DEV_FILE |
| edit_mode | in_place |

**Routing Rules:**

| Route | Target |
|---|---|
| onsuccess | review_meta |
| loop_returns_to | review_meta |

**Purpose:** Refine generated meta content files based on review feedback. Reads the review document and applies corrections to the affected meta content files in place. Only modifies files that received feedback. After refinement, routes back to review_meta for re-evaluation.

---

### Step 5: validate_meta

- **Name:** validate_meta
- **Type:** action
- **Action function:** validate_meta (from workflows/codebase_to_meta_v1/actions.py)
- **Role policy:** N/A (action-driven)

**Artifact Bindings:**

| Binding | Value |
|---|---|
| required_inputs | META_DEV_FILE, META_ARCH_FILE, META_EXEC_FILE, META_INDEX, AUDIENCE_INDEX |
| produces | VALIDATION_FILE |
| result_meta_key | VALIDATION_FILE |

**Routing Rules:**

| Route | Target |
|---|---|
| onsuccess | create_meta_backup |

**Purpose:** Structurally validate all generated meta content files. Check that each file has valid YAML frontmatter with required fields (title, audience, audience_label, generated_date, source_version, section_count). Verify that audience IDs match the AUDIENCE_INDEX. Verify that section_structure from each audience definition is reflected in the output. Check file encoding is UTF-8. Return APPROVED if all files pass, REJECTED if any file fails structural checks.

## Terminal Steps

| Step Name | Type | Description |
|---|---|---|
| step_completion | action (shared) | Standard terminal step from sdlc_shared_actions.py. Marks workflow as COMPLETED. |

**Failure Routing:**

| Step | Failure Mode | Behavior |
|---|---|---|
| validate_meta | REJECTED (structural check fails) | Workflow halts. No automatic recovery. Human intervention required to fix meta content files. |
| review_meta | on_reject_refine exhausted (max_iterations = 2) | Failure code: REFINE_EXHAUSTED. Failure class: HUMAN_RETRY_REQUIRED. Workflow halts for human intervention. |
| Any action step | Action returns REJECTED | Workflow halts at that step. Human intervention required. |
