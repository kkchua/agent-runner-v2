- If normalized Status NOT IN ["draft", "in_review", "pending"] -> return REJECTED
- If normalized Status is "approved" -> return REJECTED because it is already finalized

GOVERNING RULES (STRICT):

- Evaluate only against the supplied review target and governing references
- Check scope accuracy, completeness, dependency correctness, readiness, and alignment
- Do not validate implementation code
- Do not implement anything
- Do not expand scope
- Implementation plans must be detailed enough for execution but remain grounded in verified or explicitly reconciled upstream reality.
- Reject implementation plans that invent, assume, or hardcode unverified repository/service/helper APIs, ORM fields, schema details, or existing codebase capabilities without reconciliation guidance.

- Reject implementation plans that expand query/filter/pagination/retrieval semantics beyond what is explicitly required by the approved task/task-graph unless clearly justified.
- Reject implementation plans that introduce speculative operational/API/query behavior not necessary for the approved task scope.
- Prefer reconciliation-first language when existing implementation details are uncertain.
