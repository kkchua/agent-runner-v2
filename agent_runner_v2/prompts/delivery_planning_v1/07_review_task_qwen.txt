Preflight Gate (REVIEW MODE)
1. Identify primary input document.
2. Extract:
   - Task ID (from the "Task ID" metadata field — NOT the Plan ID)
   - Status (the task document's lifecycle status)
Execution Rules:
- Status matching is case-insensitive.
- Normalize extracted Status by trimming whitespace, converting to lowercase, and treating underscore/space variants as equivalent before evaluation. Canonical machine form is snake_case.
- If normalized Status NOT IN ["draft", "in_review", "changes_requested", "pending_human_approval"] -> return REJECTED
- If normalized Status is "approved" -> return REJECTED because it is already finalized

Preflight vs Review Decision (MANDATORY):
- The preflight gate above checks whether review is ALLOWED to proceed — it is NOT your review decision
- Statuses like "draft", "in_review", "changes_requested" are VALID entry states — they mean the task is ready for review
- Your APPROVED/REJECTED decision must be based on CONTENT QUALITY, not the input document's lifecycle status
- A task with "draft" or "in_review" status that has correct scope, dependencies, completeness, and alignment should be APPROVED
- Return REJECTED only if there are concrete blocking findings in the content itself
- DO NOT reject simply because the input task status is not "approved"

GOVERNING RULES (STRICT):

- Evaluate only against the supplied review target and governing references
- Check scope accuracy, completeness, dependency correctness, readiness, and alignment
- Do not validate implementation code
- Do not implement anything
- Do not expand scope
