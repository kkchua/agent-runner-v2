## Decision Details

### ADR-001: v2 Architecture with Sidecar-Only Communication

**Context**: v1 relied on parsing stdout JSON, which was fragile and error-prone.

**Decision**: Use `meta.json` sidecar as the ONLY communication channel between coder and runner.

**Consequences**:
- Positive: Reliable structured communication; no stdout parsing
- Positive: Clear contract between components
- Negative: Requires explicit sidecar writing in prompts
- Mitigation: Automatic sidecar instruction injection (ADR-010)

### ADR-003: Centralized constants.py for All Paths

**Context**: Hardcoded paths scattered across codebase created maintenance burden.

**Decision**: Single constants.py module with ARTIFACT_KEY_*, FOLDER_KEY_*, and pre-computed paths.

**Consequences**:
- Positive: Single source of truth for all paths
- Positive: Supports runtime path flexibility
- Negative: Large constants file
- Mitigation: Logical grouping; clear naming conventions

### ADR-006: Schema Versioning for Job State

**Context**: Job state format changes risk breaking in-progress jobs.

**Decision**: CURRENT_SCHEMA_VERSION = 6; automatic migration on load.

**Schema History**:

|---------|--------|
| 1-5 | Legacy v1 schema evolution |

### ADR-010: Automatic Sidecar Instruction Injection

**Context**: Prompts contained boilerplate sidecar instructions causing maintenance burden.

**Decision**: Remove instructions from prompts; inject automatically at runtime via SIDECAR_INSTRUCTION_TEMPLATE.

**Consequences**:
- Positive: Simplified prompt maintenance
- Positive: Consistent injection behavior
- Negative: Requires runtime modification of prompts
- Mitigation: Clean template-based injection
