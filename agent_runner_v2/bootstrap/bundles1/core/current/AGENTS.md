## Codebase Documentation Obligations

All agents must adhere to these codebase documentation obligations:

### Universal Obligations (All Agents)

1. **Document-first principle** — No code change without corresponding documentation artifact
2. **Artifact traceability** — All documentation updates trace to initiative → plan → task → implementation
3. **Protected document compliance** — Workflow-generated documents cannot be manually edited; use source prompts instead
4. **Meta.json sidecar** — Every coder/runner step produces valid meta.json

### Planner Obligations

- **Documentation-scope capture** — Plans must identify which modules/components require documentation updates
- **Staleness assessment** — Evaluate current documentation freshness for affected areas
- **Documentation milestones** — Include documentation tasks in plan timeline

### Task Decomposer Obligations

- **Documentation-scope decomposition** — Break documentation requirements into atomic task contracts
- **Task specificity** — Each task contract specifies target modules and update type (new, modify, remove)
- **Dependency mapping** — Link documentation tasks to corresponding code tasks

### Impl Planner Obligations

- **Design doc updates** — Implementation designs include documentation modification approach
- **API alignment** — Ensure documented APIs match planned implementation
- **Change impact anticipation** — Identify which module docs will need updates

### Executor Obligations

- **Code-doc co-modification** — Modify documentation files in same step as code changes
- **Meta.json production** — Produce valid meta.json sidecar documenting changes made
- **Path constant usage** — Use centralized constants for all artifact paths; zero hardcoded strings
- **Protected doc compliance** — Do not manually edit workflow-generated documents

### Reviewer Obligations

- **Doc accuracy validation** — Verify documented APIs match implemented code
- **Completeness check** — Ensure all required doc sections present and substantive
- **Staleness flagging** — Identify outdated guidance in reviewed documentation
- **Codebase-doc reference** — Explicitly validate codebase documentation updates alongside code changes

### Memory Manager Obligations

- **Knowledge capture** — Record institutional knowledge from workflow executions
- **Cross-reference maintenance** — Link memory entries to originating artifacts and change IDs
- **Codebase-doc lessons** — Capture documentation maintenance patterns and pitfalls
- **Expiry management** — Define when memories become stale relative to project evolution
