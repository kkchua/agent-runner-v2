## Inheritance Rules

Metadata conventions inherit downward across layers:

1. **Layer 1** defines the baseline field names (`doc_type`, `authority`, `scan_policy`, `scan_reason`) and the baseline vocabularies for those fields.

2. **Layer 2** (this platform) extends the vocabularies with platform-specific values (`platform_standard`, `bundle_definition` for `doc_type`; `platform-owned`, `bundle-owned` for `authority`) and adds platform-specific fields (`platform`, `template_id`, `managed_by`). Layer 2 must not redefine the meaning of Layer 1 baseline values.

3. **Layer 3** bundles inherit both the Layer 1 baseline and the Layer 2 platform extensions. Bundles may apply platform-specific values defined by their parent Layer 2 and may add bundle-local frontmatter fields, but must not:
   - Redefine Layer 1 baseline values.
   - Redefine Layer 2 platform-specific values.
   - Claim `authority` above their owning layer (`platform-owned` is reserved for Layer 2; `bundle-owned` is the highest authority a Layer 3 bundle may claim).

4. **No lower layer may redefine the meaning of values defined by a higher layer.** A Layer 3 bundle cannot change what `platform_standard` or `platform-owned` mean; a Layer 2 platform cannot change what `masterplan` or `system` mean.
