# System Documentation Index

This directory contains the Layer 1 ecosystem governance master documents for
the agent-runner workflow orchestration system. These documents define reusable
governance rules, documentation standards, bundle taxonomy, and runtime
operating models that apply across repositories and plugin workflow ecosystems.

## Layering Model

The documentation architecture uses a three-layer model:

### Layer 1: Ecosystem Governance (This Directory)

Layer 1 documents define reusable governance rules that apply to all repositories
and plugin workflow ecosystems. They establish:

- Documentation authority and structure rules
- Bundle class definitions and ownership boundaries
- Runtime publish/install/control-plane expectations
- Validation gates for governance compliance
- Generic contracts for plugin workflow bundles

Layer 1 documents must remain generic and must not define:
- Concrete workflow identifiers
- Repository-specific artifact inventories
- Repository-specific scaffold names
- Repository-specific output examples

### Layer 2: Repository Master Docs

Layer 2 documents define repository-specific master documentation and operating
structure. These are owned by repository-level bootstrap workflows and live in
repository-specific locations such as:

- Repository root governance documents (QWEN.md, CLAUDE.md, AGENTS.md)
- Repository-level workflow registry and inventory
- Repository-specific system overview and architecture docs

Layer 2 documents derive from Layer 1 governance but add repository-specific
details, concrete workflow inventories, and local operating procedures.

### Layer 3: Plugin Workflow Families

Layer 3 documents are generated by plugin workflow bundles during execution.
These include:

- Workflow execution artifacts
- Generated documentation
- Delivery and codebase analysis outputs
- Validation and review reports

Layer 3 artifacts are managed by individual workflow executions and follow the
ownership rules defined in Layer 1 bundle taxonomy.
