Objective

Generate the complete set of master document templates for the SDLC delivery system.
These templates define the canonical structure for all delivery documents produced by
Layer 3 AI-Driven SDLC workflows.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2 platform contract.
- Generate only template documentation -- not planning, backlog, or implementation artifacts.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only reference inputs.
- Templates are universal: shared across all repositories via the global runtime path.

Reference Inputs

- Read Layer 1 governance at GOVERNANCE_RUNTIME_ROOT for metadata requirements.
- Read Layer 2 platform constitution at PLATFORM_RUNTIME_ROOT for platform contract.
- Read master template designs at SDLC_MASTER_TEMPLATE_ROOT for structural guidance.
- Read codebase context from CODEBASE_DOC_ROOT to understand repository conventions.

Template Document Requirements

Each template must include:

1. YAML Frontmatter (REQUIRED):
   - template_id: appropriate SYS-XX identifier
   - version: "1.0.0"
   - doc_type: "bundle_definition"
   - authority: "workflow-generated"
   - scan_policy: "include"
   - scan_reason: descriptive reason (e.g., "SDLC delivery document template for <type>")
   - managed_by: "workflow-generated"
   - layer: "layer3"
   - platform: "agent-runner-v2"
   - lifecycle_status: "template"

2. Required Sections:
   - Purpose statement
   - Required YAML frontmatter fields for instances of this template
   - Required content sections (in order)
   - Content guidelines
   - Naming convention for instances
   - Cross-references to related templates and agent contracts

3. Content Guidelines:
   - Templates must be generic enough for any initiative
   - Must enforce consistent structure across all instances
   - Must reference Layer 1 governance metadata requirements
   - Must align with the approval gate model from the L3 spec

Output Instructions

- Write each template to its corresponding SDLC_TEMPLATE_* artifact path.
- Use ASCII-only characters (no em-dashes, curly quotes, or Unicode).
- Use plain text section headings.
- Keep terminology consistent with Layer 1 and Layer 2 governance docs.
- Each template must be self-contained with clear usage instructions.
- Do NOT create .meta.json sidecar files for individual artifact files.
- Do NOT report .meta.json files in the artifacts dict of your result.
- Only report the declared artifact keys (SDLC_TEMPLATE_REGISTRY, SDLC_WORKFLOW_SOP, etc.).

Forbidden Content

- Layer 1 governance redefinition or contradiction
- Layer 2 platform contract redefinition
- Repo-specific content (templates are universal)
- Implementation details or code examples
- Agent contract content (generated in a separate step)
