# Builder Output Artifacts

Builder-type workflows produce executable agent-runner-v2 workflow packages.
The output is split between **LLM-generated domain logic** and **mechanically
assembled infrastructure** — the LLM never writes structural files.

## LLM-Generated Artifacts (Domain Logic)

The LLM produces these through the domain steps (implement_domain):

| Artifact Key | Filename Pattern | Description |
|---|---|---|
| `WORKFLOW_ACTIONS_FILE` | `actions.py` | Python @action functions for action-type domain steps |
| `WORKFLOW_PROMPTS_DIR` | `prompts/*.txt` | LLM prompt templates for prompt-type domain steps |
| `WORKFLOW_REQUIREMENTS_FILE` | `requirements.txt` | Python dependencies for the generated workflow |

Impl-specific overrides (also LLM-generated):
- `impls/{name}/actions.py` — action overrides (optional)
- `impls/{name}/prompts/*.txt` — prompt overrides per implementation

## Mechanically Assembled (by _assemble_package action)

These are built from the Analysis JSON by the `_assemble_package` action —
no LLM involvement. The template system reads identity, domain_steps,
artifact_keys, and implementations from the Analysis JSON.

| Artifact Key | Filename Pattern | Description |
|---|---|---|
| `WORKFLOW_MANIFEST_FILE` | `workflow.toml` | Step definitions, routing (onsuccess chains), identity, implementation declarations |
| `WORKFLOW_EXTENSIONS_FILE` | `context_extensions.py` | Artifact key registration, runtime context builder (extends WorkflowExtensions) |
| `IMPL_OVERRIDE_FILES` | `impls/*/impl.yaml` | Implementation override declarations |

## Deployed (by _promote_workflow_package action)

After assembly, the `_promote_workflow_package` action deploys the complete
package to `workflows/{codename}/`.

| Artifact Key | Filename Pattern | Description |
|---|---|---|
| `WORKFLOW_PACKAGE_DIR` | `workflows/{codename}/` | Final deployed workflow package directory |
| `README_MD` | `README.md` | Auto-generated from workflow.toml metadata if not provided |

## Final Directory Structure

After promotion, the deployed workflow package:

```
workflows/{codename}/
├── workflow.toml              ← assembled from Analysis JSON
├── context_extensions.py      ← assembled from Analysis JSON
├── actions.py                 ← LLM-generated domain actions
├── README.md                  ← auto-generated by promote
├── requirements.txt           ← LLM-generated
├── prompts/                   ← LLM-generated
│   ├── 02_<step_name>.txt
│   ├── 03_<step_name>.txt
│   └── ...
└── impls/                     ← assembled + LLM-generated
    ├── <impl_name_1>/
    │   ├── impl.yaml          ← assembled from Analysis JSON
    │   ├── actions.py         ← LLM-generated (optional)
    │   └── prompts/           ← LLM-generated
    │       └── ...
    └── <impl_name_2>/
        └── ...
```

## Quality Gate Artifacts

The AGB pipeline produces these during generation:

| Artifact Key | Filename Pattern | Description |
|---|---|---|
| `ANALYSIS_JSON_FILE` | `ANALYSIS_JSON-001.json` | Structured analysis of the input requirement |
| `DOMAIN_PLAN_FILE` | `DOMAIN_PLAN-001.md` | Detailed implementation plan with action/prompt step plans |
| `PLAN_CHALLENGE_FILE` | `PLAN_CHALLENGE-001.md` | Adversarial analysis finding potential failures |
| `IMPL_CRITIQUE_FILE` | `IMPL_CRITIQUE-001.md` | Code-level review of generated actions.py |
| `PACKAGE_REVIEW_FILE` | `PACKAGE_REVIEW-001.md` | Structural consistency check |
| `VALIDATION_FINDINGS_FILE` | `VALIDATION_FINDINGS-001.md` | Deterministic validation results |
| `GATEKEEP_PACKAGE_FILE` | `GATEKEEP_PACKAGE-001.md` | Final approve/reject verdict |

## Constraints

- All generated workflow packages must be executable via `ukbe-run-agent run --template-group <name>`
- Generated actions.py must follow the @action decorator pattern with keyword-only args
- Assembled context_extensions.py uses correct imports from agent_runner_v2.workflow_packages.workflow_extensions
- Generated prompts must include artifact placeholders and validation checklists
- Assembled impl.yaml files declare override mappings matching step names in workflow.toml
