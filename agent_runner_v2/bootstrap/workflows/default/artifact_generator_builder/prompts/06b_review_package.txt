# Self-Challenge Protocol

Follow these steps IN ORDER. Do NOT skip to the verdict.

## Step 1: Hidden Error Hunt

Read ALL generated files. Then list:
- **2 hidden errors** — broken cross-references between files, artifact key mismatches between workflow.toml and context_extensions.py, prompt placeholders that reference nonexistent keys, action names that do not match registered functions
- **1 weak assumption** — something the package assumes about the runtime environment but does not verify
- **1 missing fact** — a file, artifact key, or routing entry that should exist but does not

For each item, quote the specific text and file, and explain WHY it is wrong.

## Step 2: Functional Viability — Mental Execution

Mentally execute the workflow as the daemon would:
1. Parse workflow.toml — does it load without errors?
2. Start at init_step — follow the routing chain to completion
3. For each step — resolve its prompt file path, verify the file exists, check that all `{placeholder}` keys in the prompt are provided by context_extensions.py
4. For each action step — verify the action name matches a function in actions.py
5. Check artifact flow — every step's required_inputs are produced by prior steps

If any step fails this mental execution, that is a defect.

## Step 3: Devil's Advocate

Argue AGAINST this package. Pretend you are an opposing expert who wants to prove this package will fail at runtime. What is the strongest argument you can make?

## Step 4: Verdict

After completing steps 1-3, give your verdict:
- **PASS** — The package is executable. Any issues found are cosmetic and will not cause runtime failures.
- **REJECT** — The package has defects that will cause runtime failures. State what must be fixed.
