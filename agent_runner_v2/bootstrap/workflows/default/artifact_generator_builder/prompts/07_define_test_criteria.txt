# Objective

Define test criteria for the generated action code. You are specifying WHAT
must be tested — not writing the tests themselves.

The generated actions.py contains action functions that implement deterministic
logic (file parsing, data transformation, constraint validation). Each function
must be tested for correctness, edge cases, and error handling.

# Instructions

## Step 1: Read the Action Code

Read {WORKFLOW_ACTIONS_FILE} thoroughly. For each @action-decorated function,
identify:
- What inputs it reads (from context dict, state dict, files)
- What transformations it performs
- What outputs it produces (ActionResult with artifacts)
- What error paths exist (REJECTED outcomes, reject_codes)
- What formats/variants it claims to support

## Step 2: Read the Plan Contracts

Read {IMPLEMENTATION_PLAN_FILE} and {COMPOSITION_STANDARD_FILE} to understand:
- What each action step is supposed to accomplish (from task descriptions)
- What acceptance criteria each task defines (these become test criteria)
- What constraints the action must enforce
- What invariants must hold

## Step 3: Define Test Criteria

For EACH action function, define test criteria covering:

### Normal Path Tests
- What valid inputs produce a correct APPROVED result?
- What does the output artifact look like?

### Error Path Tests
- What happens when required inputs are missing?
- What happens when input files don't exist?
- What happens when input content is empty or malformed?

### Format/Variant Tests
- If the action claims to support multiple formats (e.g., .txt, .md, .pdf),
  define a test for EACH format. Verify the code actually handles each one —
  not just that it claims to.
- If the action has format-specific logic, test each branch.

### Constraint Enforcement Tests
- What constraints does the action validate (e.g., word count limits, language
  matching, non-empty output)?
- Define tests that verify constraints are enforced (valid data passes,
  invalid data is REJECTED).

### Edge Cases
- Boundary values (empty strings, single characters, very large inputs)
- Unicode / non-ASCII content
- Files with mixed line endings

## Step 4: Also Check Implementation-Specific Actions

If impls/ directories exist with their own actions.py files, read those too.
Define test criteria for each implementation-specific action function.
