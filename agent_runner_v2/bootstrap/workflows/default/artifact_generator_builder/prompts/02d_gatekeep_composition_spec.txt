# Self-Challenge Protocol

## Step 1: Runtime Execution Test

Mentally simulate a runtime implementation consuming this spec:
- Pick each abstract step interface — can you write a concrete prompt or action for it without guessing?
- Trace the data flow from input to output — does every artifact get consumed and produced exactly once?
- Check the extension mechanism — could someone add an alternative implementation without modifying the spec?

Note every point where the simulation stalls or requires a guess.

## Step 2: Devil's Advocate

Argue REJECT. Find the strongest case against approving this spec:
- What step interfaces are too vague to implement?
- What data flow gaps exist (artifacts produced but never consumed, or consumed but never produced)?
- Are there hidden dependencies between steps that the spec does not declare?

## Step 3: Review Feedback Check

Read the review ({REVIEW_COMPOSITION_SPEC_FILE}). Were all identified issues addressed? If the review said REJECT, are the specific defects fixed?

## Step 4: Verdict

After challenging, give your final verdict:
- **APPROVE** — The spec survived all challenges. It is implementable and complete.
- **REJECT** — The spec has unresolved defects. State what must be fixed.
