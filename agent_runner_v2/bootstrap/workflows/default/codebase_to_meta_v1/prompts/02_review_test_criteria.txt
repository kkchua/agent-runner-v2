# Objective

Review the acceptance criteria document for completeness, correctness,
and testability. Produce a review verdict (APPROVED or REJECTED).

This step produces the REVIEW_TEST_CRITERIA_FILE.

## Reference Inputs

Read the following files before producing any output:

- TEST_CRITERIA_FILE: {TEST_CRITERIA_FILE}
  Review the complete test criteria document. Check each criterion
  for specificity, verifiability, and traceability.

- WORKFLOW_SPEC_FILE: {WORKFLOW_SPEC_FILE}
  Cross-reference criteria against the spec to verify coverage.
  Pay attention to all sections the criteria should cover.

## Review Checklist

1. **Coverage completeness** -- Every spec section (2 through 5.5)
   has corresponding acceptance criteria.

2. **Criterion specificity** -- No criterion uses vague language
   like "must be correct" or "must work properly." Each criterion
   is objectively verifiable.

3. **Traceability** -- Each criterion can be traced to a specific
   spec section.

4. **Phase coverage** -- All 9 phases have dedicated criteria sections.

5. **v3 innovation coverage** -- Criteria exist for composition
   standard (Phase 6) and meta composition spec (Phase 7).

6. **Negative criteria** -- Criteria define what MUST NOT appear
   in outputs.

7. **Self-validation** -- The criteria document includes a
   self-validation section verifying its own completeness.

## Decision Rules

Return APPROVED if:
- All checklist items pass
- No vague or unverifiable criteria remain
- All 9 phases are covered

Return REJECTED if:
- Any phase is missing criteria
- Criteria contain vague language
- Spec sections are not covered

## Self-Critic

Challenge your review before producing the verdict:
- Did you actually read every criterion, or did you skim?
- Did you check each criterion against the spec, not just the
  criteria document?
- Are there missing phases or spec sections you overlooked?

## Output Instructions

Use file-writing tools to write the review verdict to:
{REVIEW_TEST_CRITERIA_FILE}

Format: Markdown with YAML frontmatter
Include the APPROVED or REJECTED verdict prominently.
List specific issues if REJECTED.

ASCII-only content.

The result field in meta.json is for status summary ONLY. Write all
content to the file specified above.
