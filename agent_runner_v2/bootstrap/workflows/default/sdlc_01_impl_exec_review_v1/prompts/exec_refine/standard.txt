Objective

Refine the execution document based on gatekeep findings.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2 platform contract.
- Refine only the execution document, not validation artifacts.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only authority.

Reference Inputs

- Read {EXEC_FILE} (the execution document to refine).
- Read {GATEKEEP_FILE_SUGGESTED} (gatekeep findings with specific feedback).
- Read {IMPL_FILE} (approved implementation plan for traceability verification).
- Read the actual codebase to verify changes.

Refinement Rules

1. Address ALL Failed Gate Checks:
   - IMPL Completeness: implement any missing code, re-run tests.
   - Test Accuracy: fix fabricated or inaccurate test results.
   - Regression: fix any new failures introduced by the changes.
   - Challenge Resolution: resolve any remaining unresolved findings.
   - Documentation: correct any inaccurate file paths, snippets, or commands.

2. Verify Every Fix:
   - After making changes, run the test suite again.
   - Record actual test output, not expected output.
   - Update the relevant sections of {EXEC_FILE} with verified results.

3. Preserve Original Intent:
   - Do not invent new execution steps not performed.
   - Do not add validation reports or review documents.
   - Maintain traceability to {IMPL_FILE}.

4. Update the Challenge Resolution Section:
   - Add entries for any new findings from {GATEKEEP_FILE_SUGGESTED}.
   - Ensure all resolutions cite verifiable evidence.

5. Verify Technical Accuracy:
   - Verify API and SDK usage against the actual installed library version.
   - Check code snippets and file paths against the actual codebase.

Output Instructions

- Update {EXEC_FILE} in place with the refined content.
- Preserve the YAML frontmatter.
- Keep frontmatter fields present and consistent.
- Use plain text section headings.
- Do not change the document structure unless required by gatekeep findings.

Forbidden Content

- Layer 1 governance redefinition or contradiction
- Layer 2 platform contract redefinition
- Scope not covered by the approved implementation plan
- Fabricated test output
- Content not supported by the actual execution performed
