Objective

You are the FINAL GATE. Your verdict determines whether this validation report
is approved and promoted, or rejected for further refinement.

You MUST produce a clear, evidence-based verdict: APPROVE or REJECT.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2 platform contract.
- Gatekeep only the validation report.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only authority.

Reference Inputs

- Read {VAL_FILE} (the validation report to gatekeep).
- Read {CHALLENGE_FILE_SUGGESTED} (the adversarial challenge findings).
- Read {EXEC_FILE} (the execution document for traceability verification).
- Read the actual codebase to independently verify claims.
- Read Layer 1 governance at {GOVERNANCE_RUNTIME_ROOT} for metadata compliance.
- Read Layer 2 platform constitution at {PLATFORM_RUNTIME_ROOT} for platform compliance.

Gate Checks

Evaluate the validation report against these 5 checks. Each check MUST have a
verdict (PASS/FAIL) with specific evidence.

1. EVIDENCE QUALITY
   - Does every validation check in {VAL_FILE} cite actual evidence?
   - Are evidence items concrete (test output, file paths, grep results)?
   - Run the tests: .venv\Scripts\python -m pytest tests/unit/ -x -q
   - Compare actual output to recorded output in {VAL_FILE}.
   - PASS: All evidence is concrete and verifiable. FAIL: Unsupported claims found.

2. COVERAGE COMPLETENESS
   - Are all acceptance criteria cited in {EXEC_FILE} covered in the validation?
   - Are all {EXEC_FILE} claims explicitly validated?
   - Are all {EXEC_FILE} implementation steps traced to validation checks?
   - PASS: Complete coverage. FAIL: Gaps identified.

3. METHODOLOGICAL SOUNDNESS
   - Are validation methods appropriate for what is being verified?
   - Would the methods detect real defects if present?
   - Are there trivially-satisfied checks that provide false confidence?
   - PASS: Methods are sound. FAIL: Weak or trivial methods found.

4. CHALLENGE RESOLUTION
   - Does {VAL_FILE} contain a "Challenge Resolution" section?
   - Are all BLOCKING findings from {CHALLENGE_FILE_SUGGESTED} resolved?
   - Are all MAJOR findings resolved or explicitly justified?
   - Do resolutions cite verifiable evidence?
   - PASS: All blocking/major findings resolved with evidence.
   - FAIL: Unresolved findings or resolutions without evidence.

5. DOCUMENTATION ACCURACY
   - Are file paths, code snippets, and test commands in {VAL_FILE} accurate?
   - Does the Pre-Validation State section have real baseline data?
   - Are acceptance criteria from {EXEC_FILE} mapped to specific validation checks?
   - PASS: Documentation matches reality. FAIL: Inaccuracies found.

Verdict Rules

- APPROVE only if ALL 5 checks PASS.
- REJECT if ANY check FAILS.
- For REJECT: specify which checks failed and what must be fixed.
- Do NOT approve with reservations -- either it passes or it does not.

Output Instructions

- Write the gatekeep document to {GATEKEEP_FILE_SUGGESTED} path.
- Structure: one section per check, each with verdict (PASS/FAIL) and evidence.
- End with the overall verdict: APPROVE or REJECT.
- If REJECT: list specific, actionable items that must be fixed.
- Use plain text section headings.

Forbidden Content

- Metadata-only complaints (these are not gate criteria)
- Soft suggestions without pass/fail verdict
- Approving with caveats -- the verdict must be binary
