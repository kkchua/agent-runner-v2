Objective

Generate the full staged Layer 1 governance foundation set for
`01_governance_foundation_v1`.

Layer Boundary

- This workflow belongs to Layer 1 only.
- Generate governance content only.
- Do not define runtime architecture, install procedures, publish
  procedures, registry operations, platform-specific contracts, or
  bundle-local artifact mappings.

Reference Inputs

- Read `MASTERPLAN_ARCHITECTURE_PATH`.
- Read `MASTERPLAN_WORKFLOW_SPEC_PATH`.
- Read `GOVERNANCE_CONTEXT_INVENTORY`.

Artifacts

Write all six permanent staged docs:

- `L1_FOUNDATION_INDEX`
- `L1_LAYER_MODEL`
- `L1_DOCUMENT_AUTHORITY`
- `L1_BUNDLE_TAXONOMY`
- `L1_GOVERNANCE_LIFECYCLE`
- `L1_METADATA_STANDARD`

Required Content

- `README.md` must index the governance set and state that Layer 1 excludes
  runtime and platform implementation detail.
- `README.md` must include itself in the document map so the published set
  inventory remains six documents, not five companions plus an implicit
  index.
- `LAYER_MODEL.md` must define Layer 1, Layer 2, Layer 3, their
  boundaries, dependency direction, and promotion overview.
- `DOCUMENT_AUTHORITY.md` must define authority vocabulary, authority
  matrix, promotion constraints, and permanent-vs-temporary rules.
- `BUNDLE_TAXONOMY.md` must define the conceptual bundle taxonomy and make
  clear that workflow-specific artifact contracts are not owned by Layer 1.
- `BUNDLE_TAXONOMY.md` must stay conceptual. Do not describe bootstrap or
  delivery mechanics such as copying templates, seeding workflows,
  initializing repository structure, or one-time setup procedures.
- `GOVERNANCE_LIFECYCLE.md` must define lifecycle states, approval versus
  publication, revision, deprecation, retirement, and promotion
  interaction.
- `METADATA_STANDARD.md` must define required metadata fields, baseline
  vocabularies, scan policy rules, scanner compliance rules, and validation
  expectations.

Required Structure Per Document

Each document must use the exact template_id and include the required
section headings listed below. Before writing any file, verify the
template_id and all headings are present.

| Document | template_id | Required Section Headings |
|---|---|---|
| `README.md` | `SYS-00-IDX` | Document Map |
| `LAYER_MODEL.md` | `SYS-00-LM` | Layer 1, Layer 2, Layer 3, Relationship Between Layers |
| `DOCUMENT_AUTHORITY.md` | `SYS-00-DA` | Authority Vocabulary, Document Authority Matrix, Promotion Rules |
| `BUNDLE_TAXONOMY.md` | `SYS-00-BT` | Bundle Classes, Ownership Rules |
| `GOVERNANCE_LIFECYCLE.md` | `SYS-00-GL` | Lifecycle States, Publication Rule, Promotion And Lifecycle Interaction |
| `METADATA_STANDARD.md` | `SYS-00-MS` | Required Metadata Fields, Allowed Scan Policy Values, Scanner Compliance Rules |

Required Frontmatter

Each permanent document must include YAML frontmatter with at least:

- `template_id`
- `version`
- `doc_type: "system"`
- `authority: "workflow-generated"`
- `scan_policy: "include"`
- `scan_reason`
- `layer: "layer1"`
- `lifecycle_status: "draft"`
- `effective_version: "{job_id}"`

Forbidden Content

- runtime governance manuals
- install or publish procedures
- registry operations
- platform-specific runtime details
- repository-specific operating instructions
- Layer 3 output inventories
- operational bootstrap mechanics such as copying templates, seeding
  workflows, or one-time repository setup instructions

Output Instructions

- Write complete markdown files to the exact paths above.
- Use ASCII only.
- Keep terminology consistent across all six docs.
- These are staged run outputs, not active published docs yet.
- Staged permanent docs must use `lifecycle_status: "draft"`. Publish-state
  values such as `published` belong only to the publish step.
