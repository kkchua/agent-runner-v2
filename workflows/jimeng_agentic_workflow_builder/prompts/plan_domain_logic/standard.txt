# Planning Protocol

### Domain Step Design:

The domain_steps in the Analysis JSON define the TARGET workflow's pipeline.
They describe what the target workflow DOES — not how it's built or deployed.
Infrastructure (workflow.toml, context_extensions.py, assembly, promotion) is
handled by the platform after domain logic is generated.

Typical domain step pattern:
1. **Parse/extract input** → action step to parse the input format
2. **Analyze structure** → prompt step to analyze the input
3. **Design target** → prompt step to plan the target output
4. **Generate domain logic** → prompt step to produce actions.py + prompts

## Step 1: Plan Each Action Step

For every domain_step with type="action", specify:

### Function Design
- **Function name**: Must match action_name from Analysis JSON.
- **Purpose**: One sentence describing what this function does.
- **Input artifacts**: Which artifact keys it reads from state["artifacts"].
- **Output artifacts**: Which artifact keys it writes.
- **Core logic**: Describe the algorithm in pseudocode or detailed steps.
- **Format handling**: If the action processes files, specify which formats
  are supported and how each is parsed. Do NOT claim format support without
  real parsing logic. If a format requires an external library, declare it
  in requirements.txt.

### Validation Rules
- What input validations does this action perform at its boundary?
- What conditions cause REJECTED vs APPROVED?
- What reject_codes are defined?

### Error Handling
- What can go wrong in this action?
- How does the action signal failure (ActionResult status, reject_code)?

## Step 2: Plan Each Prompt Step

For every domain_step with type="prompt", specify:

### Prompt Design
- **Prompt filename**: Must match prompt_file from Analysis JSON.
- **Purpose**: What the LLM should accomplish when executing this prompt.
- **Input sections**: What context the prompt receives (artifact placeholders).
- **Output instructions**: What the LLM must produce and where to write it.
- **Validation checklist**: Self-check items the LLM must verify before
  completing.

### Data Flow
- What artifact placeholders does the prompt reference? (e.g., {PARSED_DOCUMENT})
- What does the LLM write, and which artifact key captures the output?

### Role Policy Justification
- Why is this role_policy appropriate for this step?

## Step 3: Map the Complete Data Flow

Produce a data flow diagram (text-based) showing:

```
INPUT ARTIFACTS
    |
    v
[Step 1: action_name] -- produces --> INTERMEDIATE_A
    |
    v
[Step 2: prompt_file] -- consumes INTERMEDIATE_A -- produces --> INTERMEDIATE_B
    |
    v
...
    |
    v
[Step N: ...] -- produces --> OUTPUT ARTIFACTS
```
