# Generation Tasks

## Part A: Workflow Package

Generate the executable workflow files per the step sequence and artifact contract:
1. workflow.toml -- step definitions with prompt=/action= for EVERY step (this IS the default implementation), routing, artifact bindings (name = {CODENAME})
2. context_extensions.py -- artifact key registration, path resolution
3. actions.py -- @action implementations for action-driven steps
4. prompts/ -- one .txt per prompt-driven step
5. README.md -- target workflow documentation
6. Specs/ -- copy the requirement doc ({REQUIREMENT_DOC}) to this folder for the generated workflow

**CRITICAL: The init step MUST declare `required_inputs` in its `[step.artifacts]` section.** This tells the operator console what input files to prompt the user for. Example:

```toml
[[step]]
name = "parse_input"
action = "parse_input_document"
onsuccess = "next_step"

[step.artifacts]
required_inputs = ["INPUT_FILE"]
produces = ["PARSED_DOCUMENT"]
result_meta_key = "PARSED_DOCUMENT"
```

Without `required_inputs` on the init step, the operator console cannot show file pickers and the workflow will fail at runtime due to missing input.

## Part C: Alternative Implementations (REQUIRED)

The composition spec identifies at least one output variant. You MUST create the `impls/{name}/` directory and declare it in workflow.toml for each variant.

1. Create `impls/{name}/` directories with partial overrides
2. Declare each implementation in workflow.toml using `[[workflow.implementation]]`

Each alternative implementation directory contains:
- `impl.yaml` (required) -- ONLY the steps that differ from the default workflow.toml
- `actions.py` (optional) -- impl-specific action functions
- `prompts/` (optional) -- impl-specific prompt templates

**impl.yaml format:**

```yaml
name: variant_name
description: "Brief description of this variant"

overrides:
  step_name:
    prompt: "impls/variant_name/prompts/01_step.txt"
  another_step:
    action: "variant_action"
```

**workflow.toml declaration** (add after `[workflow]` section):

```toml
[[workflow.implementation]]
name = "variant_name"
description = "Brief description of this variant"
label = "Display Label"
```

The `default` implementation (workflow.toml itself) is always implicitly available — do NOT list it. Each `name` MUST match an `impls/{name}/` directory.

**Rules:**
- Each key under `overrides:` MUST match a step name in workflow.toml
- Each override MUST specify `prompt` or `action` (at least one)
- Steps NOT listed inherit from workflow.toml unchanged
- Override prompt paths are relative to the workflow package root
- Every `[[workflow.implementation]]` name MUST have a matching `impls/{name}/` directory

# Required Output Folder Structure

The output folder ({out}) IS the workflow package folder that will be deployed/published. It MUST have this structure:

```
output/
    standards/
        COMPOSITION_STANDARD.md  <- composition standard (abstract step interfaces)
    impls/                       <- REQUIRED: at least one alternative variant
        {variant_name}/
            impl.yaml            <- partial overrides (only steps that differ)
            actions.py           <- optional variant-specific actions
            prompts/             <- optional variant-specific prompts
                *.txt
    Specs/
        *.md                     <- requirement docs for this generator
    workflow.toml                <- step sequence + DEFAULT implementation
    context_extensions.py        <- artifact key registration
    actions.py                   <- shared actions (all impls can reuse)
    prompts/                     <- shared prompts (all impls can reuse)
        *.txt
    README.md                    <- workflow documentation
```

IMPORTANT: The `impls/` directory MUST contain at least one alternative implementation. The default implementation lives entirely in `workflow.toml` — there is NO `impls/default/` directory. Each alternative MUST have a matching `[[workflow.implementation]]` entry in workflow.toml.
