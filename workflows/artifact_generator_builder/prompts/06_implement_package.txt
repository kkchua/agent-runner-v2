# Implementation Protocol

## Step 1: Read the Plan

Read {IMPLEMENTATION_PLAN_FILE} completely. For each task, note:
- What file/function to create
- Dependencies (must be completed before this task)
- Acceptance criteria (what tests will verify)

## Step 2: Implement Task-by-Task

Work through tasks in dependency order. For each task:

1. Create the file or function as specified
2. Verify each acceptance criterion is met
3. Move to the next task

### Critical Rules for Action Functions

Each action function MUST:
- Import `from agent_runner_v2.workflow_packages.actions import action` and `from agent_runner_v2.action_result import ActionResult`
- Be decorated with `@action("action_name")`
- Use signature `(context, state, step_cfg, project_root)`
- Return `ActionResult(status=..., remark=..., artifacts=...)`
- **Contain a COMPLETE, WORKING implementation.** No stubs, no placeholder fallbacks, no unsupported format claims.
- **If the function claims to support a format (e.g., .pdf, .docx), it MUST contain real extraction logic for that format.** Not just a try/except that reads binary as text. If you cannot implement real support for a format, do NOT claim to support it — remove it from the format map.
- **Every branch must produce a meaningful result.** No dead-code branches where all paths return the same value.

### Critical Rules for Prompt Files

Each prompt file MUST:
- Reference only artifact keys that exist in context_extensions.py
- Include all algorithm instructions from the runtime impl
- Use `{placeholder}` syntax for artifact references

### Critical Rules for workflow.toml

The workflow.toml MUST:
- Have every step assigned to either `prompt` or `action`
- Have every step's `required_inputs` produced by prior steps
- Have routing that reaches step_completion without cycles
- Declare `[[workflow.implementation]]` for each variant (not `default`)
- Include `required_inputs` on the init step for operator console file pickers

## Step 3: Self-Check Against Acceptance Criteria

After implementing all tasks, go back to the plan. For EACH acceptance criterion:
- Can you verify it's met? Point to the specific code/file that satisfies it.
- If not met, fix it before proceeding.
