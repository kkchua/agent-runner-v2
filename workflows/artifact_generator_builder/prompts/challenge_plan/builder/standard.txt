# Attack Protocol

## Step 1: Attack Each Action Plan

For every planned action function, ask:

- **Format gaps**: "The plan says it handles .txt and .json. What happens when
  the input is a .csv? A .pdf with no text layer? An empty file? A 50MB file?"
- **Logic flaws**: "The plan describes extracting sections by heading. What
  happens when headings are nested? When there are no headings? When headings
  contain special characters?"
- **Missing validations**: "The plan reads a JSON file but doesn't validate
  the schema. What happens when required keys are missing? When values are
  wrong types?"
- **Boundary failures**: "The plan splits text by paragraphs. What happens
  when the input has no paragraph breaks? When paragraphs are 10,000 words
  each?"
- **Dead code paths**: "The plan describes branch A for format X and branch B
  for format Y. What happens for format Z? Does the function crash, return
  garbage, or silently skip?"

## Step 2: Attack Each Prompt Plan

For every planned prompt template, ask:

- **Ambiguity**: "The prompt says 'analyze the document'. What specific
  analysis? What format should the output take? What if the document contains
  images?"
- **Missing constraints**: "The prompt asks the LLM to extract key points but
  doesn't specify how many. What prevents the LLM from returning 1 point or
  1000?"
- **Placeholder gaps**: "The prompt references {PARSED_DOCUMENT} but the
  action plan doesn't guarantee this artifact exists when the prompt runs."
- **Output format**: "The prompt doesn't specify the output format. Will the
  LLM write markdown? JSON? Prose? Does it matter for downstream consumers?"
- **Self-validation weakness**: "The prompt's self-check says 'verify
  completeness' but doesn't define what complete means for this domain."

## Step 3: Attack the Data Flow

Trace data from input to output. At each step boundary:

- **Lost data**: "Step 1 parses the document and extracts only text. What
  about metadata, tables, or structure that Step 3 needs?"
- **Transform correctness**: "Step 2 transforms format A to format B. Is the
  transformation lossless? Can Step 3 reconstruct what it needs from format B?"
- **Missing links**: "Step 4 requires artifact key X, but no prior step
  produces it. Where does X come from?"
- **Race conditions**: "Step 3 reads an artifact that Step 2 writes. But Step
  2's prompt doesn't explicitly write to that artifact path."

## Step 4: Attack Implementation Overrides

For each alternative implementation:

- **Incomplete overrides**: "The override changes the prompt for step 2 but
  step 2's output format changes. Does step 3 (shared, not overridden) still
  consume the new format correctly?"
- **Implicit assumptions**: "The override assumes the shared action produces
  output in format X, but the shared action's plan doesn't guarantee format X."
- **Override conflicts**: "Two overrides both modify steps that depend on each
  other. Are the interactions defined?"

## Step 5: Attack Edge Cases

Think about the requirement doc's domain. What edge cases does the plan ignore?

- Empty inputs, malformed inputs, extremely large inputs
- Unicode content, mixed-language content, content with special characters
- Concurrent access, partial failures, timeout scenarios
- Domain-specific edge cases (e.g., for a summarizer: single-sentence input,
  input shorter than the target summary)

# Severity Definitions

- **BLOCKING**: The plan cannot produce working code without addressing this.
  The action will crash, return wrong results, or the prompt will produce
  unusable output.
- **MAJOR**: The plan will produce code that works for happy paths but fails
  on realistic edge cases. Degraded functionality or incorrect output.
- **MINOR**: Unlikely edge case or quality concern. The code works but could
  be more robust.

# Rules

- Produce AT LEAST 5 attacks. Fewer than 5 means you didn't look hard enough.
- Every attack MUST be specific. "The plan might not handle edge cases" is
  NOT an attack. "When input is a 50-page PDF with no text layer, parse_input
  returns empty string, causing analyze_structure to produce zero ScoredUnits,
  causing render_output to produce an empty file" IS an attack.
- Focus on FUNCTIONAL viability. Do NOT attack infrastructure (workflow.toml
  structure, context_extensions.py patterns) — those are assembled mechanically.
- Do NOT suggest solutions. Your job is to attack, not fix.
- Do NOT soften your language. State failures directly.
- Do NOT include non-ASCII characters.
- Do NOT reference old AGB concepts (composition spec, runtime impl, artifact
  contract).
