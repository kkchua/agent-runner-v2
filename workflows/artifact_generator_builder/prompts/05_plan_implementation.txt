# Objective

Break the approved design into a structured implementation task list. Each task defines ONE file or function to create, with explicit acceptance criteria that tests will later verify.

This task list is the CONTRACT between design and implementation. The implementation step follows it exactly. The testing step verifies each task's acceptance criteria.

# Planning Protocol

## Step 1: Identify All Implementation Units

Read the runtime implementation and artifact contract. List every file and function that must be created:

**Files:**
- workflow.toml
- context_extensions.py
- actions.py
- One prompt file per prompt-driven step
- README.md
- standards/COMPOSITION_STANDARD.md (copy from design phase)
- impls/{name}/ directories (if variants exist)

**Functions (within actions.py):**
- Each @action-decorated function
- Helper functions needed by actions

**Variant files (if variants exist):**
- impls/{name}/impl.yaml
- impls/{name}/actions.py (if variant-specific actions)
- impls/{name}/prompts/*.txt (if variant-specific prompts)

## Step 2: Define Each Task

For each implementation unit, create a task with:

```
### Task T-NNN: <title>
**Type:** file | function | prompt | config
**Creates:** <filename or function name>
**Depends on:** <list of task IDs that must be completed first>
**Description:** <what this task produces>
**Acceptance Criteria:**
- AC-1: <specific, testable condition>
- AC-2: <specific, testable condition>
- ...
```

### Acceptance Criteria Rules

Every acceptance criterion MUST be:
- **Testable:** A test can verify this with a specific input/output pair
- **Specific:** "Handles .pdf files" is NOT specific. "extract_document_text('test.pdf') returns the text content of all pages joined with double newlines" IS specific.
- **Format-aware:** If a function claims to support multiple formats, there MUST be one acceptance criterion per format.
- **Error-aware:** If a function can encounter errors, there MUST be acceptance criteria for error paths.

### Required Acceptance Criteria by Task Type

**Action functions MUST have:**
- At least one normal-path test (valid input -> APPROVED with correct output)
- One test per claimed format (e.g., .txt, .md, .pdf, .docx)
- At least one error-path test (missing input, malformed input, empty input)
- Constraint enforcement tests (if the function validates constraints)

**Prompt files MUST have:**
- The prompt references only artifact keys that exist in context_extensions.py
- The prompt includes all algorithm instructions from the runtime impl

**workflow.toml MUST have:**
- Every step has either `prompt` or `action` assigned
- Every step's required_inputs are produced by prior steps
- Routing chain reaches step_completion without cycles

## Step 3: Order Tasks by Dependency

Sort tasks so dependencies come first. Typical order:
1. workflow.toml (defines the structure)
2. context_extensions.py (registers artifact keys)
3. Action functions (shared, used by multiple steps)
4. Prompt files (one per prompt-driven step)
5. Variant files (impl.yaml, variant actions, variant prompts)
6. README.md
7. standards/COMPOSITION_STANDARD.md

## Step 4: Self-Validate

Before writing the plan, verify:
- Every action function in the runtime impl has a task
- Every prompt-driven step in the runtime impl has a task
- Every format claimed by any action has an acceptance criterion
- Every error path has an acceptance criterion
- No task is missing dependencies
