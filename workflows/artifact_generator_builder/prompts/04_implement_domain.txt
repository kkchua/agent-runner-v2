actions.py and the prompt templates in prompts/. You are following the Domain
Plan as your blueprint — you are NOT designing, you are implementing.

The infrastructure files (workflow.toml, context_extensions.py, impl.yaml) are
assembled mechanically by the assemble_package action. You do NOT write those.

and address every finding before proceeding.

# Implementation Protocol

## Part A: Write actions.py

Write to: {WORKFLOW_ACTIONS_FILE}

### Required Structure

```python
"""Domain actions for {workflow_name}.

"""

@action("action_name_here")

    artifacts = state.get("artifacts", {})
    project_root = Path(project_root)

    # ... implementation ...

    return ActionResult(
        status="APPROVED",
        remark="Description of what was done",
        artifacts={"OUTPUT_KEY": str(output_path)},
    )
```

### MANDATORY Action Rules

1. **Decorator**: Every action function MUST be decorated with
   `@action("action_name")` where action_name matches the Analysis JSON's
   domain_steps[].action_name.

2. **Signature**: Every action function MUST use keyword-only arguments:
   `(*, context, state, step_cfg, project_root)`.

3. **Return type**: Every action function MUST return an `ActionResult` with
   status ("APPROVED" or "REJECTED"), remark (string), and artifacts (dict).

4. **Boundary validation**: Every action MUST validate its inputs at the
   function boundary. Check that required artifact paths exist, are readable,
   and contain parseable data. Return REJECTED with a descriptive reject_code
   on validation failure.

5. **Complete implementations**: Every function MUST contain a COMPLETE,
   WORKING implementation. No stubs, no placeholder fallbacks, no
   "TODO: implement" comments. If a function claims to support a format,
   it MUST contain real extraction logic for that format.

6. **No false format claims**: If the function cannot genuinely parse a format
   (e.g., binary PDF with no text layer), do NOT claim to support it. Remove
   unsupported formats from the format map rather than adding try/except
   wrappers that silently produce garbage.

7. **Meaningful error paths**: Every branch MUST produce a meaningful result.
   No dead-code branches where all paths return the same value. Every REJECTED
   path MUST have a distinct reject_code.

8. **Artifact writes**: When writing output artifacts, the function MUST write
   to the path specified by the artifact key in state["artifacts"]. Create
   parent directories as needed.

## Part B: Write Prompt Files

Write each prompt template to: {WORKFLOW_PROMPTS_DIR}{prompt_filename}

### MANDATORY Prompt Rules

1. **Input section**: Every prompt MUST clearly list what inputs the LLM
   receives, using `{PLACEHOLDER}` syntax for artifact paths.
   Example: `PARSED_DOCUMENT: {PARSED_DOCUMENT}`

2. **Output section**: Every prompt MUST specify exactly where to write the
   output and what format to use.
   Example: `Write to: {TRANSFORMED_CONTENT}`

3. **Domain instructions**: The prompt MUST contain all domain-specific
   instructions from the Domain Plan. Do not assume the LLM knows the domain.

4. **Validation checklist**: Every prompt MUST include a self-validation
   section before the output instructions. The checklist items MUST be
   specific to the domain (not generic "check your work").

5. **Placeholder consistency**: Every `{PLACEHOLDER}` referenced in the prompt
   MUST correspond to an artifact key in the Analysis JSON's artifact_keys.
   Do not reference keys that don't exist.

6. **Forbidden content in prompts**:
   - Do NOT reference infrastructure files (workflow.toml, context_extensions.py)
   - Do NOT reference old AGB concepts (composition spec, runtime impl)
   - Do NOT include non-ASCII characters

## Part C: Write Implementation-Specific Files

For each alternative implementation in the Analysis JSON that has overrides:

### Impl-specific actions
If an override specifies a different action, write the function to:
`impls/{impl_name}/actions.py`

Use the same action contract (decorator, signature, return type). The function
name MUST match the override's action name.

### Impl-specific prompts
If an override specifies a different prompt, write the file to:
`impls/{impl_name}/prompts/{prompt_filename}`

Follow the same prompt rules as Part B. The prompt MUST implement the variant
strategy described in the Domain Plan.

# meta.json Reporting

When writing your meta.json sidecar, report ONLY these artifact keys:

- `WORKFLOW_ACTIONS_FILE` — path to the shared actions.py
- `WORKFLOW_PROMPTS_DIR` — path to the prompts/ directory

Do NOT report implementation-specific files (impls/*/actions.py, impls/*/prompts/)
in meta.json. Those are tracked by the assemble_package step (step 6) under
`IMPL_OVERRIDE_FILES`. Reporting undeclared artifact keys causes a
STEP_CONTRACT_MISMATCH rejection.
