### Test Rules

1. **Real file I/O for format tests.** If testing .pdf/.docx handling, create
   actual test files (or minimal valid files) on disk. Do NOT mock file reads —
   the whole point is to verify the code actually processes the format.

2. **Test every @action function.** No function may be skipped.

3. **Test every format.** If an action claims .txt, .md, .pdf, .docx support,
   there must be a test for each format.

4. **Test every reject_code.** If an action can return REJECTED with specific
   reject_codes, test that each reject_code is returned for the right input.

5. **Test constraint enforcement.** If the action validates constraints (word
   count, language match, etc.), test that valid data passes and invalid data
   is rejected.

6. **Use tmp_path fixture.** For test files, use pytest's tmp_path fixture
   to create temporary files that are cleaned up automatically.

7. **Minimal valid test files.** For format tests:
   - .txt/.md: write plain text content
   - .pdf: create a minimal valid PDF (use reportlab if available, or write
     raw PDF bytes for a single-page text PDF)
   - .docx: create a minimal valid DOCX (use python-docx if available, or
     create a minimal ZIP with the required XML structure)

## Step 4: Coverage Check

After generating all tests, verify:
- Count test functions per action function
- Count test functions per format
- Count test functions per reject_code
- Every TC-NNN from the criteria has at least one test
