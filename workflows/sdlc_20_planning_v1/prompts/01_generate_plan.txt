Objective

Generate a structured solution architecture plan from the approved requirement document.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2 platform contract.
- Generate only planning documentation, not backlog, task, or implementation artifacts.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only reference inputs.

Reference Inputs

- Read `REQ_FILE` (approved requirement document).
- Read codebase context from `docs/repo/codebase/` to understand repository structure.
- Read Layer 1 governance at `GOVERNANCE_RUNTIME_ROOT` for metadata requirements.
- Read Layer 2 platform constitution at `PLATFORM_RUNTIME_ROOT` for platform contract.

Plan Document Requirements

The PLAN document must include:

1. YAML Frontmatter (REQUIRED):
   - `template_id: "SYS-03-PL"`
   - `version: "1.0.0"`
   - `doc_type: "workflow_output"`
   - `authority: "workflow-generated"`
   - `scan_policy: "include"`
   - `scan_reason: "solution architecture plan for initiative"`
   - `layer: "layer3"`
   - `platform: "agent-runner-v2"`
   - `lifecycle_status: "draft"`
   - `effective_version: "{job_id}"`
   - `managed_by: "workflow-generated"`

2. Required Sections (in this exact order):
   - `Plan Overview` - High-level summary of the solution approach
   - `Requirement Traceability` - Link back to approved REQ and key requirements
   - `Solution Architecture` - Technical approach and architecture decisions
   - `Component Breakdown` - Major components and their responsibilities
   - `Integration Points` - How components connect and interact
   - `Data Flow` - How data moves through the solution
   - `Risk Assessment` - Technical risks and mitigation strategies
   - `Dependencies` - External dependencies and prerequisites
   - `Open Questions` - Unresolved items that need clarification

3. Content Guidelines:
   - Base all decisions on the approved requirement document
   - Normalize into canonical structure without inventing scope
   - Record explicit assumptions where information is missing
   - Identify codebase areas likely affected
   - Note any audit/compliance sensitivity

Output Instructions

- Write the plan document to `PLAN_FILE` path.
- Use ASCII-only characters (no em-dashes, curly quotes, or Unicode).
- Use plain text section headings (no backticks or formatting in headings).
- Keep terminology consistent with Layer 1 and Layer 2 governance docs.
- Do not create backlogs, task graphs, or implementation artifacts.

Forbidden Content

- Layer 1 governance redefinition or contradiction
- Layer 2 platform contract redefinition
- Implementation details or code
- Task breakdowns or scheduling (belongs to backlog phase)
- Backlog items or user stories
