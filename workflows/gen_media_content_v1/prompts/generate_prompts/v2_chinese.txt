# 任务目标

你的任务是将 {STEP_01_DIR} 中每个图像描述 JSON 转换为高质量的图像提示词 JSON 和视频提示词。

# 主题变体目标

以描述 JSON 作为概念类别的灵感来源。
你的目标是生成共享相同主题概念但探索不同具体主体、风格和环境的创意变体。

变换示例：
- 浑浊池塘中的鱼 → 水晶池中的锦鲤 → 山间河流中的鲑鱼 → 深海水母
- 热带山坡 → 秋季森林 → 雪山 → 沙漠沙丘 → 城市花园
- 日出海滩 → 日落悬崖 → 月光湖泊 → 黎明薄雾 → 黄昏城市景观

可自由变化：
- 同一类别内的具体主体类型
- 环境设置和条件
- 摄影方法（自然、电影、黄金时段、情绪化、高对比度）
- 光照、情绪、氛围
- 天气和季节

保持核心概念类别一致，同时探索创意多样性。

# 主题变体规则

概念类别必须在每个变体中保持一致。

## 概念类别（保留）

- 核心主体类型（如：水生生物、风景、野生动物、建筑）
- 整体主题家族（如：自然、城市、人物、物体）
- 总体情绪方向（如：宁静、动感、神秘）

## 主体变化（允许）

- 具体主体身份可在类别内变化
- 主体数量可变化
- 主体物种/类型可变化（如：不同品种的鱼、不同类型的树）
- 主体存在与否可变化（某些变体可能省略次要主体）

## 场景变化（允许）

- 环境可变化（如：池塘 → 河流 → 海洋 → 水族馆）
- 位置可变化（如：公园 → 森林 → 花园 → 城市）
- 天气可变化（如：晴天 → 雨天 → 雾天 → 雪天）
- 一天中的时间可变化（如：黎明 → 正午 → 日落 → 夜晚）
- 季节可变化（如：春 → 夏 → 秋 → 冬）

## 构图变化（允许）

- 取景可变化（如：特写 → 广角 → 航拍）
- 摄像机角度可变化（如：平视 → 仰视 → 俯视）
- 景深层次可根据场景需要变化

# 变体生成

生成 N 个变体，N 由 {MEDIA_CONFIG} 中的 num_variants 字段决定（默认 4）。

每个变体探索相同的概念，但使用不同的具体主体。

变体 1

主题锚点

与原始概念相似的主体。保持与源的联系。
示例：自然池塘栖息地中的鱼和乌龟。

变体 2

环境转换

相同的概念类别，不同的环境和主体类型。
示例：清澈日本花园池中的彩色锦鲤。

变体 3

野生替代

相同的概念，野生/自然诠释，不同的主体。
示例：湍急山间河流中跳跃的鲑鱼。

变体 4

意外场景

相同的概念，不寻常或对比的环境。
示例：城市混凝土喷泉中的大鲤鱼，带有城市倒影。

如果 num_variants > 4，继续探索：
- 不同的天气条件（雨、雪、雾、风暴）
- 不同的时间（黎明、正午、日落、夜晚、黄昏）
- 不同的季节（春、夏、秋、冬）
- 不同的摄影方法（微距、广角、长焦、长曝光）
- 保持核心概念的同时最大化创意多样性

---

# 变体多样性规则

每个变体必须保留核心概念类别。

每个变体应在以下方面最大化创意多样性：

- 具体主体类型（不同物种、不同物体）
- 环境和场景（不同位置、不同背景）
- 摄影方法（自然、电影、黄金时段、情绪化、高对比度）
- 摄像机位置、高度、距离、取景、视角
- 光照方向、强度、氛围、色彩分级
- 天气和季节（自由变化）
- 情绪和情感基调

不要通过只改变一个参数来创建变体。

每个变体应探索不同的创意诠释。

每个变体在保持主题连贯性的同时应感觉视觉上截然不同。

不要在变体之间重复使用相同的句子结构。

独立重写每个提示词。

---

# 视觉风格规则

关键：所有图像提示词（t2i_prompt1）必须生成逼真的、摄影质量的图像。生成的图像用作视频生成（图生视频）的第 1 帧。非摄影风格（绘画、插图、动漫、卡通）会产生糟糕的视频效果，出现闪烁、变形和时间不一致。

## 强制风格：逼真摄影

每个变体必须使用摄影风格。变体之间的视觉多样性来自不同的摄影技术，而不是不同的艺术媒介。

重要：限制仅针对渲染风格，而非主体内容。奇幻、科幻、超现实、梦幻和想象主体都是允许的 — 它们必须简单地渲染为好像由真实相机拍摄。把它想象成电影剧照或高端 VFX 镜头，而不是绘画。

允许的逼真非真实主体示例：
- 双太阳的科幻外星行星（渲染为电影 VFX 剧照）
- 生物发光树木的奇幻森林（渲染为电影镜头）
- 漂浮岛屿的超现实梦幻场景（渲染为照片）
- 夜晚的赛博朋克城市景观（渲染为编辑摄影）
- 水下魔法领域（渲染为自然纪录片镜头）

禁止的渲染示例：
- 同一科幻行星用油画风格绘制
- 同一奇幻森林作为水彩插图
- 同一梦幻场景作为动漫或卡通

## 允许的摄影风格

- 自然摄影（户外、可用光）
- 电影摄影（戏剧性光照、电影般的色彩分级）
- 编辑摄影（杂志质量、精致）
- 风景摄影（宽景深、清晰细节）
- 微距摄影（极端特写、浅景深）
- 野生动物摄影（长焦压缩、自然行为）
- 建筑摄影（干净线条、透视控制）
- 街头摄影（抓拍、城市氛围）
- 艺术摄影（创意光照、情绪驱动 — 但仍是摄影）
- 长曝光摄影（水面运动模糊、光轨）

## 严格禁止的风格（会破坏视频渲染）

- 油画 / 厚涂 / 笔触纹理
- 水彩 / 水墨
- 数字绘画 / 概念艺术 / 场景绘制
- 动漫 / 卡通 / 赛璐璐着色
- 插图 / 钢笔墨水 / 图形艺术
- 素描 / 木炭 / 铅笔
- 3D 渲染 / CGI 外观
- 像素艺术 / 体素
- 点画 /  stipple
- 任何非摄影艺术媒介

## 如何添加"绘画感"或"艺术感"

如果源图像描述暗示艺术感，仅通过摄影手段实现：
- 柔和散景和浅景深（不是笔触）
- 黄金时段或蓝色时段光照（不是绘制的天空）
- 胶片颗粒和模拟色调（不是水彩渲染）
- 镜头光晕和光学效果（不是数字绘画叠加）
- 选择性对焦和移轴（不是插图技术）

## 通过摄影区分变体

每个变体应使用不同的摄影方法：

- 变体 1：自然摄影 — 忠于源图像的光照和情绪
- 变体 2：电影感 — 戏剧性侧光、更深阴影、电影色彩分级
- 变体 3：黄金时段 — 温暖方向光、长阴影、琥珀色调
- 变体 4：情绪化/氛围感 — 雾、薄雾、阴天、柔和去饱和色调
- 变体 5：高对比度 — 强烈方向光、大胆阴影、鲜艳色彩

如果 num_variants > 5，继续变化：
- 不同焦距（广角与长焦压缩）
- 不同景深（深对焦与奶油散景）
- 不同视角（低角度、高角度、平视、荷兰角）
- 不同天气条件（晴朗、阴天、雨天、雪天 — 摄影性）
- 不同时间（黎明、正午、日落、蓝色时段、夜晚）

所有变体必须保持逼真。无例外。

# 视频提示词规则

假设生成的图像是第 1 帧。视频提示词（t2v_prompt1）描述第 1 帧的确切内容在视频持续时间内的运动。

## 黄金法则

在视频提示词中写下任何文字之前，先在心中列出第 1 帧中可见的每个物体、表面和元素。视频提示词只能引用该列表中的元素。如果元素不在第 1 帧中，它就不存在于视频中 — 句号。

## 视频提示词模板

使用以下精确模式构建每个 t2v_prompt1：

"[摄像机运动]，[现有元素 1] [运动动词]，[现有元素 2] [运动动词]，[关于现有元素的大气细节]。"

提示词中的每个名词必须是第 1 帧中可见的元素。
每个动词必须来自下面的允许动词列表。

## 允许的动词（仅限现有元素的运动）

摄像机动词：推进、平移、倾斜、升降、环绕、推近、拉远、跟踪
水动词：流动、涟漪、拍打、冲击、涌流、漂流、反射、闪烁
植物动词：摇摆、弯曲、沙沙作响（仅限现有树木/植物 — 不是生长）
云/天空动词：飘动、移动、翻滚（仅限现有云 — 不是形成）
光动词：移动、消退、闪烁、舞动（仅限现有光）
主体动词：行走、游泳、漂浮、滑行、转身、移动（仅限现有主体）
粒子动词：漂流、悬浮、散落（仅限现有粒子）

## 摄像机运动多样性（强制要求）

关键：每个变体必须使用不同的摄像机运动。永远不要在变体之间重复相同的摄像机运动。

在编写视频提示词之前，从下面的池中选择 N 种不同的摄像机运动（其中 N = num_variants）：

摄像机运动池：
- 静态摄像机（固定，无运动）
- 缓慢向前推进（推近）
- 缓慢向后拉远（拉远）
- 从左向右平移
- 从右向左平移
- 向上倾斜
- 向下倾斜
- 向上升起（垂直升高）
- 向下降低（垂直下降）
- 向左环绕（围绕主体的圆周运动）
- 向右环绕（围绕主体的圆周运动）
- 向左跟踪（横向移动）
- 向右跟踪（横向移动）
- 组合：推进 + 平移（向前同时平移）
- 组合：升起 + 倾斜（上升同时向下倾斜）

随机摄像机分配（强制要求）：
在为每张图像生成提示词之前，运行以下 shell 命令随机抽取 N 种不同的摄像机运动（将 N 替换为 num_variants 值）：

shuf -e "static" "dolly-forward" "dolly-backward" "pan-left" "pan-right" "tilt-up" "tilt-down" "crane-up" "crane-down" "orbit-left" "orbit-right" "track-left" "track-right" | head -n N

按返回的顺序将抽取的摄像机运动分配给变体 1..N。
如果无法执行 shell 命令，在内部模拟随机洗牌并确保选择的集合不是相同的默认集合。

摄像机运动规则：
1. 每个变体集中的每个变体必须使用不同的摄像机运动
2. 摄像机运动集合必须在每次运行和每张图像之间不同
3. 禁止默认：永远不要对所有变体使用相同的摄像机运动
4. "静态摄像机"在每张图像集中最多出现一次
5. 优先使用动态运动（推进、平移、升降、环绕）而非静态

## 禁止的动词（暗示创造、出现或消失）

永远不要使用这些动词 — 它们会导致视频中的物体出现/消失：

- 生长、发芽、涌现、出现、实体化
- 出现、淡入、进入视野
- 消失、消散、淡出、溶解
- 变形、变身、成为、变成
- 生成、创造、形成、发展
- 升起（当暗示新物体升起到画面中时）
- 落下（当暗示新物体落入画面时 — 落叶、下雨）
- 进入、到达、接近（来自画面外的新主体）
- 离开、出发、退出（现有主体离开画面）

## 禁止的元素（无论场景背景如何）

这些元素不得出现在视频提示词中，除非在第 1 帧中已经可见。视频 API 会渲染提示词描述的任何内容 — 如果你提到它，它就会出现在即使它不在源图像中。

- 鸟类、蝙蝠、昆虫、蝴蝶（任何飞行生物）
- 落叶、花瓣、种子、碎片
- 跳跃的鱼、跃出水面的海豚
- 雨、雪（除非在第 1 帧中可见）
- 不在第 1 帧中的船只、车辆、人物
- 不在第 1 帧中的树木、岩石、建筑物
- 雾、薄雾、霾（除非在第 1 帧中可见）

## 场景特定的幻觉触发器（高风险）

视频 API 具有强大的训练关联，会覆盖负面提示词。对于这些场景，你必须在 t2v_prompt1 中包含正面反指令。

海滩/海洋/大海：
  触发：API 将水场景与鸟类、海鸥、海豚关联
  必须在 t2v_prompt1 中包含："水面上方清澈空旷的天空"
  可以描述：波浪运动、泡沫、表面反射、沙地纹理
  不要描述：棕榈树、海鸥、海豚、船只、贝壳

森林/林地：
  触发：API 将森林与落叶、鹿、鸟类关联
  必须在 t2v_prompt1 中包含："静止的空气，没有落叶"
  可以描述：树木摇摆（现有树木）、光线透过树冠
  不要描述：落叶、鹿、鸟类、蘑菇

山/悬崖：
  触发：API 将山与鹰、云层形成、雪关联
  必须在 t2v_prompt1 中包含："空旷的天空，没有翱翔的鸟"
  可以描述：现有云飘动、山峰上光线移动
  不要描述：鹰、云层形成、降雪

瀑布/河流：
  触发：API 将瀑布与升起的雾、鱼、彩虹关联
  必须在 t2v_prompt1 中包含："瀑布上方没有升起的雾"
  可以描述：水流、现有雾的运动、水雾
  不要描述：彩虹、鱼、出现的岩石

城市/都市：
  触发：API 将城市与出现的汽车、走入的人关联
  必须在 t2v_prompt1 中包含："静态场景，没有新车辆或人进入"
  可以描述：现有交通流、现有灯光、现有运动
  不要描述：出现的汽车、走入的人、亮起的灯

沙漠/干旱：
  触发：API 将沙漠与移动的沙丘、骆驼关联
  必须在 t2v_prompt1 中包含："静止的沙面，没有风吹沙"
  可以描述：热浪闪烁、现有沙地纹理、静止
  不要描述：出现的仙人掌、剧烈移动的沙丘

重要："必须包含"的短语是正面指令，告诉 API 场景应该是什么样子。这比单独的负面提示词更有效。对于这些场景类型，始终包含它们。

## 正确与错误示例

错误："轻柔的海浪拍打着海岸，棕榈树摇摆，海鸥在头顶翱翔"
→ 错误原因：棕榈树和海鸥不在第 1 帧中

正确："缓慢推进，轻柔的海浪拍打着沙滩，柔软的泡沫沿水线漂流，水面微妙的灯光闪烁"
→ 正确原因：每个元素（海浪、沙子、泡沫、光）都在第 1 帧中

错误："森林活了过来，树叶轻轻飘落，一只鹿穿过树木"
→ 错误原因：落叶和鹿不在第 1 帧中

正确："静态摄像机，现有树冠在风中轻轻摇摆，斑驳的光线在森林地面上移动，微妙的大气薄雾在树木间漂流"
→ 正确原因：树木、光线和薄雾都在第 1 帧中

## 禁止的摄像机运动

视频 API 通常将运动描述解释为摄像机移动。如果 t2v_prompt1 描述了任何行走、踏步或人类视角运动的感觉，摄像机将会随着脚步弹跳而摇晃。

绝对禁止的摄像机行为：
- 行走 / 手持 / 脚步引起的摇晃
- 奔跑 / 慢跑摄像机
- POV 行走 / 身体安装 / 自拍风格
- 摇晃摄像机 / 纪录片手持
- 在空间中跟随主体（暗示行走）
- "摄像机穿过"（暗示行走路径）
- "我们看到"或"观众行走"（暗示人类视角）
- 任何第一人称视角运动

摄像机运动必须平滑、稳定、电影化 — 就像在专业推车、升降机或稳定云台上。

如有疑问，使用"静态摄像机" — 固定摄像机仅有主体/环境运动总是比摇晃的行走摄像机更好。

## 双重物体预防

视频 API 有时会复制突出的物体（月亮、太阳、行星），在天空中创建两个或更多副本。为防止这种情况：

如果第 1 帧包含月亮、太阳或其他天体：
- 在视频提示词中仅提及一次
- 使用"唯一的月亮"或"唯一的太阳" — "唯一"这个词可以防止重复
- 不要描述它移动或变化 — 只需说"唯一的月亮在天空中保持静止"或"唯一的太阳投射稳定的光"
- 不要描述多个光源

如果第 1 帧包含任何突出的单一物体（灯塔、塔楼、雕像）：
- 仅提及一次
- 使用"唯一的 [物体]"以防止重复
- 不要描述它被复制或倍增

# 输出规则

仅将所需的 JSON 文件输出到磁盘。

不要解释你的推理。

不要总结描述 JSON。

不要提及推断的细节。

保留所需的 JSON 结构。

保留所有文件名。

保留现有工作流。

保留归档生成。

保留 index.json 生成。

## 输出文件名约定

对于每个输入描述 JSON，创建一个带 `_prompts` 后缀的输出文件：

输入：{STEP_01_DIR}/image_001.json  →  输出：{STEP_02_DIR}/image_001_prompts.json
输入：{STEP_01_DIR}/beach_sunset.json  →  输出：{STEP_02_DIR}/beach_sunset_prompts.json

输出 JSON 文件名必须为：`<input_stem>_prompts.json`

## Index.json 结构

处理完所有图像后，在 {STEP_02_DIR}/ 中生成一个具有以下结构的 index.json：

```json
{
  "step": "generate_prompts",
  "files": [
    {"input": "step_01_imagedesc/image_001.json", "output": "{STEP_02_DIR}/image_001_prompts.json"},
    {"input": "step_01_imagedesc/image_002.json", "output": "{STEP_02_DIR}/image_002_prompts.json"}
  ]
}
```

将所有变体 JSON 写入 {STEP_02_DIR} 后，生成 index.json。

注意：从 {STEP_01_DIR} 归档已处理的描述文件由后续的归档步骤自动处理 — 不要自己从 {STEP_01_DIR} 归档或删除文件。

# 关键：输出机制

你必须使用文件写入工具在磁盘上创建实际文件。不要将工件数据放在 meta.json 的 result 字段中 — result 字段仅用于状态和摘要信息。

所需的文件输出：
1. 单个变体 JSON：{STEP_02_DIR}/<image_stem>_prompts.json（对应每个输入描述）
2. 索引文件：{STEP_02_DIR}/index.json 列出所有输入到输出的映射

你的 meta.json result 字段应仅包含：
- status: "complete" 或 "error"
- remark: 简短摘要（如"为 5 个描述各生成 4 个变体，写入 5 个 JSON + 索引"）
- 不要在 result 字段中包含完整的 JSON 数据

在 meta.json 的 artifacts 字段中，你必须报告：
- PROMPT_VARIANTS: 你写入的 index.json 文件的绝对路径
