Objective

Generate a structured task specification from the approved backlog.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2 platform contract.
- Generate only task specification documentation, not implementation artifacts.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only reference inputs.

Reference Inputs

- Read `BACKLOG_FILE` (approved backlog document).
- Read codebase context from `docs/repo/codebase/` to understand repository structure.
- Read Layer 1 governance at `GOVERNANCE_RUNTIME_ROOT` for metadata requirements.
- Read Layer 2 platform constitution at `PLATFORM_RUNTIME_ROOT` for platform contract.

Task Document Requirements

The TASK document must include:

1. YAML Frontmatter (REQUIRED):
   - `template_id: "SYS-03-TK"`
   - `version: "1.0.0"`
   - `doc_type: "workflow_output"`
   - `authority: "workflow-generated"`
   - `scan_policy: "include"`
   - `scan_reason: "task specification for initiative execution"`
   - `layer: "layer3"`
   - `platform: "agent-runner-v2"`
   - `lifecycle_status: "draft"`
   - `effective_version: "{job_id}"`
   - `managed_by: "workflow-generated"`

2. Required Sections (in this exact order):
   - `Task Overview` - High-level summary of the task scope
   - `Backlog Traceability` - Link back to approved BACKLOG and work item
   - `Task Scope` - Detailed scope of what this task covers
   - `Acceptance Criteria` - Specific, measurable acceptance criteria
   - `Technical Approach` - Technical approach to accomplish the task
   - `Files and Components` - Files and components affected
   - `Dependencies` - Dependencies on other tasks or external resources
   - `Risk Factors` - Task-specific risks and mitigations
   - `Open Questions` - Unresolved items that need clarification

3. Content Guidelines:
   - Base all specifications on the approved backlog document
   - Normalize into canonical structure without inventing scope
   - Record explicit assumptions where information is missing
   - Identify specific codebase files and components affected
   - Note any audit/compliance sensitivity

Output Instructions

- Write the task document to `TASK_FILE` path.
- Use ASCII-only characters (no em-dashes, curly quotes, or Unicode).
- Use plain text section headings (no backticks or formatting in headings).
- Keep terminology consistent with Layer 1 and Layer 2 governance docs.
- Do not create implementation plans or execution artifacts.

Forbidden Content

- Layer 1 governance redefinition or contradiction
- Layer 2 platform contract redefinition
- Implementation code or execution results
- Implementation planning details (belongs to implementation phase)
- Execution logs or validation results
