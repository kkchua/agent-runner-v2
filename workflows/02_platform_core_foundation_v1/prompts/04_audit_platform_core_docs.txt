Objective

Perform a final semantic audit of the staged Layer 2 platform core constitution set before human approval and publish.

Layer Boundary

- Audit for true Layer 2 correctness, not only surface quality.

Reference Inputs

- Read `MASTERPLAN_ARCHITECTURE_PATH`.
- Read `MASTERPLAN_PLATFORM_SPEC_PATH`.
- Read `PLATFORM_CONTEXT_INVENTORY`.
- Read `PLATFORM_CORE_VALIDATION`.
- Read the Layer 1 governance set at `GOVERNANCE_RUNTIME_ROOT`.
- Audit all staged permanent docs:
  `L2_PLATFORM_INDEX`, `L2_RUNTIME_MODEL`, `L2_BUNDLE_AUTHORING_CONTRACT`,
  `L2_SHARED_SERVICES`, `L2_METADATA_CONTRACT`, `L2_VALIDATION_CONTRACT`.

Forbidden Content

Reject if the final staged set:

- still redefines or contradicts Layer 1 governance
- contains bundle-specific content normalized into platform standards
- lacks clear platform identity (`agent-runner-v2`)
- normalizes temporary evidence into permanent standards
- overclaims promotion authority above Layer 2
- conflicts internally on authority, lifecycle, or metadata rules
- leaves staged permanent docs in published/active lifecycle state
- presents a runtime model that contradicts the actual platform source code

Audit Decision

- Produce an explicit decision: **APPROVED** or **REJECTED**. There is no middle
  ground, no "APPROVED with findings," and no conditional approval.
- **REJECTED**: any factual error exists -- wrong method names, wrong file paths,
  wrong class or function names, mismatched symbols, or any claim that does not
  match the actual platform source code -- even if the error is trivial to fix.
  A single incorrect API name on one line in one document requires rejection.
- **APPROVED**: every claim in every document exactly matches the platform source
  code. Zero findings. Only then is the staged set ready for human approval and
  publish.
- Always write an audit file to `AUDIT_FILE_SUGGESTED`.
- Cite offending text directly for every rejection finding, including the correct
  source-code symbol and its line number.
- If approved, summarize why the staged set is ready for human approval and publish.
- Use ASCII only in the audit artifact.

Output Instructions

Write the audit file with these sections:

- `Decision`
- `Layer Boundary Audit`
- `Authority Audit`
- `Metadata Audit`
- `Platform Identity Audit`
- `Cited Evidence`
- `Publish Recommendation`
