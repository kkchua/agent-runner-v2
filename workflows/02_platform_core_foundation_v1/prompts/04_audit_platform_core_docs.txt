Objective

Perform a final semantic audit of the staged Layer 2 platform core constitution set before human approval and publish.

Layer Boundary

- Audit for true Layer 2 correctness, not only surface quality.

Reference Inputs

- Read `MASTERPLAN_ARCHITECTURE_PATH`.
- Read `MASTERPLAN_PLATFORM_SPEC_PATH`.
- Read `PLATFORM_CONTEXT_INVENTORY`.
- Read `PLATFORM_CORE_VALIDATION`.
- Read the Layer 1 governance set at `GOVERNANCE_RUNTIME_ROOT`.
- Audit all staged permanent docs:
  `L2_PLATFORM_INDEX`, `L2_RUNTIME_MODEL`, `L2_BUNDLE_AUTHORING_CONTRACT`,
  `L2_SHARED_SERVICES`, `L2_METADATA_CONTRACT`, `L2_VALIDATION_CONTRACT`.

Forbidden Content

Reject if the final staged set:

- still redefines or contradicts Layer 1 governance
- contains bundle-specific content normalized into platform standards
- lacks clear platform identity (`agent-runner-v2`)
- normalizes temporary evidence into permanent standards
- overclaims promotion authority above Layer 2
- conflicts internally on authority, lifecycle, or metadata rules
- leaves staged permanent docs in published/active lifecycle state
- presents a runtime model that contradicts the actual platform source code
- documents wrong function signatures for `build_context_extensions`, `build_output_paths`, or `resolve_repo_or_runtime_path` that do not match the actual source code
- describes `resolve_repo_or_runtime_path()` as "check repo first, fall back to runtime" — the actual function dispatches by path prefix, not via existence-based fallback
- contains the phrases "no disk recovery functions", "no stdout JSON parsing", or "sole communication channel" paired with a denial of fallbacks in RUNTIME_MODEL.md or SHARED_SERVICES.md — the runner does repair missing/invalid sidecars via `_repair_or_validate_meta_json` in `step_runner.py`
- omits the `### BackendClient` subsection from SHARED_SERVICES.md or lists BackendClient method names that do not exist in `backend_client.py`
- uses shortened or schematic example paths (e.g., `docs/platform/README.md`) instead of the full canonical path `docs/system/00_governance/platform/current/...`

Required Audit Checks

In addition to the forbidden-content list above, the audit must explicitly verify:

- **Signature accuracy**: Cross-check every documented function signature in SHARED_SERVICES.md against the actual source code. Read `context_extensions.py` and `output_paths.py` from any bundled workflow (including this workflow's own bundle) and `runtime_context.py` from the installed `agent_runner_v2` package. Reject if any signature does not match.
- **Resolution-order accuracy**: Verify the `### Resolution Order` section in SHARED_SERVICES.md describes the actual prefix-dispatch behavior of `resolve_repo_or_runtime_path()`, not an existence-based fallback.
- **Meta sidecar accuracy**: Verify RUNTIME_MODEL.md and SHARED_SERVICES.md accurately describe both the primary sidecar channel and the repair fallback (`_repair_or_validate_meta_json`). Reject if the docs deny the repair mechanism.
- **BackendClient method accuracy**: Verify every method listed in the `### BackendClient` subsection of SHARED_SERVICES.md exists as a `def` in `backend_client.py`. Reject on any mismatch.
- **Authority / managed_by orthogonality**: Verify METADATA_CONTRACT.md's `### Usage Rules` section under `## Platform authority Values` explicitly states that `authority` (content ownership) and `managed_by` (mechanical producer) are orthogonal axes. A document carrying `authority: "platform-owned"` + `managed_by: workflow-generated` is consistent — the contract must say so. If the contract's definitions imply a contradiction between these two fields, reject with the specific inconsistency.

Audit Decision

- Produce an explicit decision: **APPROVED** or **REJECTED**. There is no middle
  ground, no "APPROVED with findings," and no conditional approval.
- **REJECTED**: any factual error exists -- wrong method names, wrong file paths,
  wrong class or function names, mismatched symbols, or any claim that does not
  match the actual platform source code -- even if the error is trivial to fix.
  A single incorrect API name on one line in one document requires rejection.
- **APPROVED**: every claim in every document exactly matches the platform source
  code. Zero findings. Only then is the staged set ready for human approval and
  publish.
- Always write an audit file to `AUDIT_FILE_SUGGESTED`.
- Cite offending text directly for every rejection finding, including the correct
  source-code symbol and its line number.
- If approved, summarize why the staged set is ready for human approval and publish.
- Use ASCII only in the audit artifact.

Output Instructions

Write the audit file with these sections:

- `Decision`
- `Layer Boundary Audit`
- `Authority Audit`
- `Metadata Audit`
- `Platform Identity Audit`
- `Cited Evidence`
- `Publish Recommendation`
