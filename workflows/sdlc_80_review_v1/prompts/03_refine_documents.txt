Objective

Refine the review, memory, and closure documents based on review findings.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2 platform contract.
- Refine all three documents: REV, MEM, and CLOSE.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only authority.

Reference Inputs

- Read `REV_FILE` (the review document to refine).
- Read `MEM_FILE` (the memory document to refine).
- Read `CLOSE_FILE` (the closure document to refine).
- Read `REVIEW_FILE_SUGGESTED` (review findings with specific feedback).
- Read `VAL_FILE` (approved validation report for traceability verification).
- Read codebase context from `docs/repo/codebase/` if needed for clarification.

Refinement Rules

1. **Address All Critical Findings**:
   - Missing required sections must be added in the relevant document(s)
   - Metadata errors must be corrected in the relevant document(s)
   - Encoding violations must be fixed in the relevant document(s)

2. **Address All Major Findings**:
   - Inaccurate content must be corrected in the relevant document(s)
   - Missing traceability must be added in the relevant document(s)
   - Contradictory statements must be resolved in the relevant document(s)

3. **Address Minor Findings** (if time permits):
   - Style issues should be improved in the relevant document(s)
   - Minor clarifications should be added in the relevant document(s)

4. **Preserve Original Intent**:
   - Do not invent new content not supported by the validation report
   - Do not add implementation details or code changes
   - Maintain traceability to the source validation documents

5. **Update Traceability**:
   - If content was refined, update the traceability sections
   - Record what was changed and why
   - Reference the review findings

Refinement Process

1. Read the review findings carefully
2. Identify which document(s) each finding applies to
3. Address each issue systematically in the relevant document(s)
4. Update all documents in place
5. Verify all required sections are present in all documents
6. Verify metadata is compliant in all documents
7. Verify encoding is ASCII-only in all documents

Output Instructions

- Update the review document in place at `REV_FILE` path.
- Update the memory document in place at `MEM_FILE` path.
- Update the closure document in place at `CLOSE_FILE` path.
- Use ASCII-only characters.
- Use plain text section headings.
- Keep frontmatter fields present and consistent in all documents.
- Do not change document structures unless required by review findings.

Forbidden Content

- Layer 1 governance redefinition or contradiction
- Layer 2 platform contract redefinition
- Implementation details or code changes
- Content not supported by the approved validation report
