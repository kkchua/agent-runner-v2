Objective

Refine the initiative document based on review findings.

Layer Boundary

- This workflow belongs to Layer 3 and operates on top of the Layer 2 platform contract.
- Refine only the initiative document, not planning or implementation artifacts.
- Treat Layer 1 governance and Layer 2 platform constitution as read-only authority.

Reference Inputs

- Read {INIT_FILE} (the initiative document to refine).
- Read {REVIEW_FILE_SUGGESTED} (review findings with specific feedback).
- Read {DRAFT_INIT_FILE} (original draft for traceability verification).
- Read codebase context from {CODEBASE_DOC_ROOT} if needed for scope clarification.

CRITICAL: Exact Artifact Key Names

When referencing artifact keys in the document, use EXACTLY these names:
  - Input artifact: DRAFT_INIT_FILE
  - Output artifact: INIT_FILE

All artifact keys use the _FILE suffix.
If the document contains incorrect key names, fix them.

Authorized Sections

The document must contain EXACTLY these sections. Do not add sections not in this list.

  1. Title
  2. Objective
  3. Problem Statement
  4. Expected Outcomes
  5. Scope (In Scope, Out of Scope, Boundary Conditions)
  6. Constraints
  7. Dependencies
  8. Success Criteria
  9. Stakeholders
  10. Notes (OPTIONAL)

Refinement Rules

1. Address Critical Findings First:
   - Add any missing required sections from the list above
   - Fix frontmatter errors
   - Fix encoding violations

2. Address Major Findings:
   - Clarify unclear scope
   - Add missing success criteria
   - Resolve contradictory statements

3. Address Minor Findings (if time permits):
   - Improve style issues
   - Add minor clarifications

4. Preserve Original Intent:
   - Do not invent new scope not supported by the draft
   - Do not add sections not in the authorized list
   - Do not add implementation details
   - Do not add task breakdowns or scheduling
   - Maintain traceability to the source draft

Output Instructions

- Update the initiative document in place at {INIT_FILE}.
- Use ASCII-only characters.
- Use plain text section headings.
- Keep frontmatter fields present and consistent.
- Do not change the document structure unless required by review findings.

Forbidden Content

- Layer 1 governance redefinition or contradiction
- Layer 2 platform contract redefinition
- Implementation details or technical solutions
- Task breakdowns or scheduling
- Architecture decisions (belongs to planning phase)
- Content not supported by the original draft
- Sections NOT in the authorized list above
